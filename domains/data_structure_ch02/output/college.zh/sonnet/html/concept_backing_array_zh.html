Backing Array

底层数组（backing array）是指在动态数据结构内部实际存储元素的那块连续内存区域。以 Python 的列表或 Java 的 ArrayList 为例，表面上看它们可以随意追加元素，但在底层，它们依赖一个固定大小的数组来存放数据。当元素数量超过当前容量时，系统会申请一块更大的新数组，将旧数据全部复制过去，再释放旧数组——这个过程称为扩容（resizing）。

理解底层数组，关键在于区分两个概念：长度（length/size）是当前实际存储的元素个数，容量（capacity）是底层数组能容纳的最大元素数。长度 $\leq$ 容量始终成立。

工作示例

用 Python 观察列表的底层容量变化：

import sys

lst = []
prev_size = sys.getsizeof(lst)
for i in range(20):
    lst.append(i)
    curr_size = sys.getsizeof(lst)
    if curr_size != prev_size:
        print(f"长度={len(lst):2d}，内存从 {prev_size} 字节跳至 {curr_size} 字节")
        prev_size = curr_size

运行后可以看到内存不是每次追加都增长，而是在特定长度（通常是 1、5、9、17……）时跳跃式扩大。这正是扩容触发的时刻。CPython 采用约 1.125 倍加常数的增长策略，使得 $n$ 次 append 的均摊时间复杂度为 $O(1)$，而非每次扩容带来的 $O(n)$。

问题求解应用

假设你需要实现一个栈，要求 push 操作的最坏情况时间复杂度严格为 $O(1)$（而非均摊）。直接基于底层数组的动态列表无法满足这一要求，因为扩容时会触发 $O(n)$ 的复制。

解决方案之一是预分配固定容量：在初始化时一次性申请足够大的底层数组，并追踪当前栈顶指针。只要元素数量不超过预设上限，每次 push 仅需将元素写入 array[top] 并令 top += 1，严格 $O(1)$。

class BoundedStack:
    def __init__(self, capacity):
        self._data = [None] * capacity  # 预分配底层数组
        self._top = -1
        self._cap = capacity

    def push(self, val):
        if self._top + 1 == self._cap:
            raise OverflowError("栈已满")
        self._top += 1
        self._data[self._top] = val

    def pop(self):
        if self._top < 0:
            raise IndexError("栈为空")
        val = self._data[self._top]
        self._top -= 1
        return val

这个例子说明：理解底层数组的存在，才能在性能敏感的场景中做出正确的设计权衡——何时接受均摊代价、何时主动控制容量。
