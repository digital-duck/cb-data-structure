列表接口

定义

列表接口（List Interface）是一种抽象数据类型规范，它定义了对有序元素集合可以执行哪些操作，而不规定这些操作在底层如何实现。换句话说，接口是一份"契约"：它声明了 append、insert、remove、get、size 等方法的名称和行为，但不关心数据究竟存储在连续内存中（数组）还是通过指针链接（链表）。这种"接口与实现分离"的思想是面向对象设计的核心原则之一。

具体示例

假设我们要构建一个待办事项管理器。无论底层使用 Python 内置列表还是自定义链表，调用方只需依赖以下接口：

class ListInterface:
    def append(self, item): ...   # 末尾添加元素
    def insert(self, index, item): ...  # 指定位置插入
    def remove(self, item): ...   # 删除首个匹配元素
    def get(self, index): ...     # 按下标读取
    def size(self): ...           # 返回元素数量

以 Python 内置 list 为例，它完整实现了上述接口：

tasks = []
tasks.append("写作业")          # ["写作业"]
tasks.insert(0, "吃早饭")       # ["吃早饭", "写作业"]
print(tasks.get(0))             # 报错！内置list用 tasks[0]
print(tasks[0])                 # "吃早饭"
tasks.remove("写作业")          # ["吃早饭"]
print(len(tasks))               # 1

注意：Python 内置列表用 tasks[index] 替代 get(index)，这正说明不同语言/框架对同一接口的语法实现可以有差异，但语义一致。

问题求解应用

理解列表接口的真正价值在于：它让你可以在不修改调用代码的前提下切换实现。假设你的待办列表需要频繁在头部插入元素。使用数组实现时，insert(0, item) 需要将所有现有元素右移，时间复杂度为 $O(n)$；而改用双向链表实现，头部插入只需调整指针，复杂度降为 $O(1)$。由于两者都遵循同一接口契约，调用代码一行不改，只需替换底层实现类即可。

这种"面向接口编程"的习惯能让你在设计阶段先专注于"需要什么操作"，再在性能分析后决定"怎么实现"——这是工程师处理大型系统时的标准思路。
