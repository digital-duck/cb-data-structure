Fast Array Stack

Definition. A fast array stack is an abstract stack (last-in, first-out) implemented over a contiguous backing array whose capacity doubles whenever the occupied size equals its length and halves whenever the occupied size falls to one-quarter of its length. Formally, let $A$ be an array of capacity $c$, and let $n$ denote the number of elements currently stored, with the invariant

$$\frac{c}{4} \;\leq\; n \;\leq\; c.$$

The three primitive operations are:

  • $\texttt{push}(x)$: if $n = c$, reallocate $A$ with capacity $2c$; then set $A[n] \leftarrow x$ and $n \leftarrow n+1$.
  • $\texttt{pop}()$: if $n = c/4$, reallocate $A$ with capacity $c/2$; decrement $n$ and return $A[n]$.
  • $\texttt{peek}()$: return $A[n-1]$ without modification.

    • Each reallocation copies all $n$ elements, costing $\Theta(n)$ in the worst case. The central question is whether repeated calls remain efficient in aggregate.

    Worked example. Start with $c = 1$, $n = 0$. Push the sequence $1, 2, 3, 4, 5$:

    | Step | Operation | $n$ | $c$ | Reallocate? | |------|-----------|-----|-----|-------------| | 1 | push(1) | 1 | 1 | no ($n < c$ after) — initial slot used | | 2 | push(2) | 2 | 2 | yes: $n=1=c$, double to $c=2$ | | 3 | push(3) | 3 | 4 | yes: $n=2=c$, double to $c=4$ | | 4 | push(4) | 4 | 4 | no | | 5 | push(5) | 5 | 8 | yes: $n=4=c$, double to $c=8$ |

    Total element-copy work across all reallocations: $1 + 2 + 4 = 7$, while the five pushes themselves cost $5$. The total work is $12$ for five operations, giving an empirical average of $2.4$ per operation.

    Theorem (Amortized $O(1)$ per operation). Assign each element a charge of $3$ units when pushed. One unit pays for the push itself; the remaining two are banked. When a doubling reallocation copies $n$ elements, each of the $n/2$ elements inserted since the last doubling has banked exactly $2$ units, collectively covering the $n$ copy operations. A symmetric argument using a charge of $2$ units handles halving. Therefore, every push and pop runs in $O(1)$ amortized time, and the worst-case time for any sequence of $m$ operations is $O(m)$.

    Lab cell.

    from sympy import symbols, summation, simplify, Integer

# Verify total copy work for k doublings starting from capacity 1
k = symbols('k', positive=True, integer=True)
# Capacities after i doublings: 2^i; copy work at doubling i is 2^(i-1)
i = symbols('i', nonneg=True, integer=True)
total_copy_work = summation(2**i, (i, 0, k - 1))
print("Total copy work for k doublings:", simplify(total_copy_work))
# Expected: 2**k - 1  (always less than final capacity 2**k)

    Running this cell yields $2^{k}-1$, confirming that total reallocation cost never exceeds the final capacity — the hallmark of geometric resizing efficiency.
