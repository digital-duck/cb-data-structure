列表接口

回顾直觉：你已经知道列表就像一排有编号的格子，可以存放数字、文字或任何数据。但"接口"这个词意味着更多——它描述的是你能对列表做什么操作，而不仅仅是列表长什么样。

探索结构：把列表接口想象成一份"操作合同"。无论内部实现如何，任何符合列表接口的数据结构都必须支持以下核心操作：

| 操作 | 符号表示 | 含义 | |------|----------|------| | 访问 | $L[i]$ | 获取位置 $i$ 的元素 | | 插入 | $L.\text{insert}(i, x)$ | 在位置 $i$ 插入元素 $x$ | | 删除 | $L.\text{delete}(i)$ | 移除位置 $i$ 的元素 | | 长度 | $\|L\|$ | 返回列表中元素的个数 |

这里有个关键思想：接口与实现分离。你可以用数组实现列表，也可以用链式结构实现——只要对外提供相同的操作，使用者根本不需要知道内部差别。

简单规律：接口定义"能做什么"，实现决定"怎么做到"。不同实现的性能可能差异很大——例如，数组的 $L[i]$ 只需 $O(1)$ 时间，而某些链式结构可能需要 $O(n)$。

课后练习：假设你有一个列表 $L = [3, 7, 1, 9]$，依次执行以下操作：

  • $L.\text{insert}(2, 5)$（在位置 2 插入 5）
  • $L.\text{delete}(0)$（删除位置 0 的元素）
