Concept Book: Dllist List Operations

Data Structure Ch03 · Generated by SPL

Payoff

A doubly-linked list is a sequence of nodes $v_1, v_2, \ldots, v_n$ in which each node $v_i$ holds a datum $d_i$ together with two pointers: $\mathrm{next}(v_i) = v_{i+1}$ and $\mathrm{prev}(v_i) = v_{i-1}$, with sentinel values $\mathrm{prev}(v_1) = \mathrm{next}(v_n) = \texttt{null}$. The collection $\texttt{dllist\_list\_operations}$ formalises the four primitive mutations—prepend, append, insert\_after, and delete—together with the two traversals forward and backward, and the predicate find. What distinguishes this ensemble from its singly-linked counterpart is the constant-time, pointer-only character of every structural change: no element is copied, and no index arithmetic is required.

Worked example. Let the list hold the integers $[10, 20, 30]$. To delete the node containing $20$, one executes precisely two pointer reassignments:

$$\mathrm{next}(\mathrm{prev}(v_{20})) \;\leftarrow\; \mathrm{next}(v_{20}), \qquad \mathrm{prev}(\mathrm{next}(v_{20})) \;\leftarrow\; \mathrm{prev}(v_{20}).$$

The list becomes $[10, 30]$ in $O(1)$ time, having touched no other node. Contrast this with an array, where deletion of an interior element forces an $O(n)$ shift.

Key theorem (complexity parity). Every operation in $\texttt{dllist\_list\_operations}$, when given a direct pointer to the target node, runs in $\Theta(1)$ time and $\Theta(1)$ additional space, regardless of list length $n$. Forward and backward traversal of the entire list both run in $\Theta(n)$ time.

This theorem is the reason the doubly-linked list sits at the heart of real systems. A text editor's gap buffer degenerates to a doubly-linked list of lines; each keystroke is an $O(1)$ insert or delete. A browser maintains its session history as a doubly-linked list so that the Back and Forward buttons both traverse in constant time per step. An operating-system run queue uses the same structure so that the scheduler can splice a newly unblocked thread into an arbitrary position without touching the rest of the queue.

Lab cell.

from sympy import symbols, Rational, pretty

# Symbolic cost comparison: doubly-linked list vs. array deletion
n = symbols('n', positive=True, integer=True)
cost_dll   = Rational(1)          # O(1)
cost_array = n                    # O(n)
speedup    = cost_array / cost_dll

print("DLL deletion cost  :", pretty(cost_dll))
print("Array deletion cost:", pretty(cost_array))
print("Speedup factor     :", pretty(speedup), "(linear in n)")

Running this cell makes the asymptotic gap concrete: for $n = 10^6$ elements the doubly-linked list completes one million deletions in the same time an array completes one. The operations are not merely elegant—they are the difference between a responsive application and a frozen one.

You now possess the full machinery. To see these ideas at their sharpest, carry the delete and insert_after operations into the design of an LRU cache, where every cache hit must promote a node to the front of the list in $O(1)$ time while the eviction policy simultaneously removes from the back. That single application will exercise every primitive you have learned and reveal why $\texttt{dllist\_list\_operations}$ is not an abstract exercise but the engine beneath software you use every day.
