Concept Book: Queue Operations Sllist

Data Structure Ch03 · Generated by SPL

Payoff

A singly linked list supports a queue when two invariants are maintained simultaneously: new elements are appended at the tail in $O(1)$ time, and elements are removed from the head in $O(1)$ time. Formally, let $L = \langle n_1, n_2, \ldots, n_k \rangle$ be a singly linked list where each node $n_i$ carries a payload $n_i.\mathit{val}$ and a pointer $n_i.\mathit{next}$. The queue abstract data type is realized by keeping two external references, $\mathit{head} \to n_1$ and $\mathit{tail} \to n_k$, so that $\mathrm{enqueue}(x)$ writes $n_{k+1}.\mathit{next} \leftarrow \varnothing$, $\mathit{tail}.\mathit{next} \leftarrow n_{k+1}$, and advances $\mathit{tail}$, while $\mathrm{dequeue}()$ reads $n_1.\mathit{val}$ and advances $\mathit{head}$—both operations touching a constant number of pointers regardless of $k$.

This is the natural endpoint of the book's progression. Earlier chapters established how a linked node can store a datum without contiguous memory; intermediate chapters showed how pointer manipulation achieves stack semantics. Queue semantics are strictly richer: they impose a total order on service—first-in, first-out—which stack semantics cannot provide. Every structure studied previously was a tool; $\mathit{queue\_operations\_sllist}$ is the first that enforces fairness as a mathematical property.

Worked example. Suppose tasks arrive with identifiers $\{A, B, C\}$ in that order. After three enqueue calls the list is $\mathit{head} \to A \to B \to C \leftarrow \mathit{tail}$. Two dequeue calls return $A$ then $B$, leaving $\mathit{head} \to C \leftarrow \mathit{tail}$. The invariant $\mathit{head} \to \cdots \to \mathit{tail}$ is preserved throughout; no element is skipped or served out of order.

Key theorem (amortized complexity). For any sequence of $n$ enqueue and $m$ dequeue operations on an initially empty linked-list queue, the total pointer-write count is $\Theta(n + m)$, yielding $O(1)$ amortized cost per operation. The proof follows immediately because each node is allocated once (one pointer write during enqueue) and deallocated once (one pointer advance during dequeue).

# Lab cell — verify FIFO ordering symbolically
from sympy import symbols, Function, Eq, Piecewise

# Model the queue length as a recurrence
n = symbols('n', nonneg=True, integer=True)
Q = Function('Q')

enqueue_step = Eq(Q(n + 1), Q(n) + 1)
dequeue_step = Eq(Q(n + 1), Q(n) - 1)

print("Enqueue recurrence:", enqueue_step)
print("Dequeue recurrence:", dequeue_step)
# Both are O(1) state transitions — constant work per step.

The reach of this structure extends far beyond toy examples. Operating system schedulers maintain a run queue of process control blocks; network switches buffer packets in hardware queues; breadth-first graph search relies on a queue to guarantee level-by-level exploration; and streaming data pipelines decouple producers from consumers through bounded queues. In each domain the underlying mathematics is identical—a pointer-threaded sequence with $O(1)$ endpoints—yet the consequences differ dramatically in scale and stakes.

If one application deserves deeper study, it is breadth-first search. The queue is not merely a convenience there; it is the mechanism that encodes distance. Each dequeue event processes a vertex at distance $d$ from the source, and every enqueue event registers a vertex at distance $d+1$. Removing the queue and substituting a stack collapses BFS into DFS, losing the distance guarantee entirely. Exploring that connection rigorously—through the lens of the queue invariant proved above—reveals why data structure choice is never cosmetic but always mathematical.
