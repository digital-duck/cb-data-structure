Concept Book: Stack Operations Sllist

Data Structure Ch03 · Generated by SPL

Payoff

A singly linked list equipped with stack operations—push, pop, and peek—represents one of the most elegant convergences in elementary data structures: a dynamic, pointer-chained sequence disciplined into a strictly last-in, first-out (LIFO) discipline. Throughout this text we built the machinery piece by piece, from node allocation and pointer arithmetic to the invariants of the linked-list spine. The stack abstraction seals that machinery into a contract: the client sees only the top of the structure and interacts with it in constant time, $O(1)$, for every operation, while the underlying chain of nodes grows and shrinks without any predetermined capacity bound.

Why this is the natural endpoint. A static array-based stack commits to a fixed allocation and requires reallocation when that bound is exceeded, introducing amortized rather than strict $O(1)$ cost and coupling the data structure to an external memory manager. The singly linked list removes both constraints. Each call to push allocates exactly one node; each call to pop deallocates exactly one. The invariant is local: the head pointer always addresses the top element, and every operation touches at most two pointers. This locality is precisely what makes the structure both provably correct and practically efficient.

Worked example. Consider evaluating the arithmetic expression $3 \; 4 \; 2 \; \times \; + $ in reverse-Polish (postfix) notation. Scan left to right. Upon encountering an operand $x$, call push(x); upon encountering a binary operator $\odot$, call b = pop(), a = pop(), and push(a \odot b). Tracing the example: push $3$, push $4$, push $2$; operator $\times$ yields $\text{pop}()=2$, $\text{pop}()=4$, push $8$; operator $+$ yields $\text{pop}()=8$, $\text{pop}()=3$, push $11$. The unique remaining element, retrieved by peek(), is the result $11$. Every step is $O(1)$; the total complexity is $\Theta(n)$ in the number of tokens.

Key theorem (stack correctness). Let $S$ be a stack implemented on a singly linked list with head pointer $h$. Then for any sequence of $k$ push operations followed by $k$ pop operations on an initially empty stack, the elements are returned in the exact reverse order of insertion. Formally, if the push sequence is $(x_1, x_2, \dots, x_k)$, the pop sequence is $(x_k, x_{k-1}, \dots, x_1)$. The proof follows directly by induction on $k$: after each push the new node becomes the head, so the most recently inserted element is always the first retrieved.

Lab cell.

from sympy import symbols, Integer

class Node:
    def __init__(self, val): self.val = val; self.next = None

class SLLStack:
    def __init__(self): self.head = None
    def push(self, v): n = Node(v); n.next = self.head; self.head = n
    def pop(self):
        if not self.head: raise IndexError("underflow")
        v = self.head.val; self.head = self.head.next; return v
    def peek(self): return self.head.val if self.head else None

tokens = [Integer(3), Integer(4), Integer(2), '*', '+']
s = SLLStack()
for t in tokens:
    if isinstance(t, Integer):
        s.push(t)
    else:
        b, a = s.pop(), s.pop()
        s.push(a * b if t == '*' else a + b)

print(s.peek())   # 11

The structures and algorithms explored here extend far beyond arithmetic. Recursive call frames in every modern runtime lean on a stack; compiler implementations of depth-first graph traversal replace the implicit call stack with an explicit one constructed from the same push/pop interface. Browser history, undo buffers, and syntax parsers for nested languages all reduce, under the surface, to the same three-operation contract you have now mastered.

Choose any one of these domains—say, depth-first search on a graph—and you will find that the singly linked list stack you have built is not merely adequate but ideal: unbounded in capacity, uniform in cost, and transparent in correctness.
