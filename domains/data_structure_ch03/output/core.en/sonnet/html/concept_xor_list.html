Xor List

Definition. An XOR linked list is a doubly linked list in which each node stores a single field $\text{npx}$ defined as the bitwise exclusive-or of the memory addresses of its predecessor and successor:

$$\text{npx}(v) = \text{addr}(\text{prev}(v)) \oplus \text{addr}(\text{next}(v)),$$

where $\oplus$ denotes the bitwise XOR operation on non-negative integers. For the head node, $\text{prev} = 0$ (the null address), so $\text{npx}(\text{head}) = \text{addr}(\text{next}(\text{head}))$; symmetrically for the tail. Because XOR is its own inverse—$a \oplus b \oplus b = a$ for all $a, b \in \mathbb{Z}_{\geq 0}$—traversal requires only the address of the previously visited node.

Worked Example. Consider a list of three nodes with (symbolic) addresses $A = 100$, $B = 200$, $C = 300$. The stored fields are:

$$\text{npx}(A) = 0 \oplus 200 = 200, \quad \text{npx}(B) = 100 \oplus 300 = 340, \quad \text{npx}(C) = 200 \oplus 0 = 200.$$

To move forward from $A$ to $B$, the traversal computes $\text{next} = \text{npx}(A) \oplus \text{addr}(\text{prev}) = 200 \oplus 0 = 200$, yielding $B$. From $B$ to $C$: $\text{next} = 340 \oplus 100 = 300$, yielding $C$. Backward traversal is identical with the roles of prev and next exchanged.

Key Theorem (Space Optimality). An XOR linked list representing $n$ nodes requires exactly $n$ pointer-width words for linkage, compared with $2n$ words for a conventional doubly linked list. Formally, if each address occupies $w$ bits, the total linkage storage is $S_{\text{XOR}} = nw$ bits versus $S_{\text{std}} = 2nw$ bits, a factor-of-two reduction. The correctness of traversal follows directly from the self-inverse property of XOR: for any three consecutive addresses $p, q, r$, the node at $q$ stores $p \oplus r$, and $(p \oplus r) \oplus p = r$, $(p \oplus r) \oplus r = p$, enabling movement in either direction from a single stored word.
