Skiplist Sset

Definition

A skiplist implements the SSet interface (find(x), add(x), remove(x)) on a sorted collection. It is a stack of linked lists:

  • Level 0 ($L_0$) contains all elements in sorted order.
  • Each higher list $L_r$ contains a random subset of $L_{r-1}$. Each element of $L_{r-1}$ is promoted to $L_r$ by an independent fair coin flip, so it appears in $L_r$ with probability $1/2$.

    • Every node $u$ has a height $h(u)$, the number of lists that contain it. It also has a next pointer for each level. A sentinel node at the head has maximum height. Heights are geometric: $\Pr[h(u) \ge k] = 2^{-(k-1)}$, so the expected height is $2$. The expected number of pointers is therefore $O(n)$.

    The key idea is a search path. Start at the top level of the sentinel. Move right while the next key is $< x$. When it would overshoot, drop down one level. At $L_0$, the next node is the smallest element $\ge x$, which is the answer to find(x).

    Worked example

    Take $L_0 = [3, 5, 8, 12, 15, 20]$, $L_1 = [5, 12, 20]$, $L_2 = [12]$. Search for $x = 15$.

  • Start at the sentinel on $L_2$. The next key is $12 < 15$, so move to $12$. The next key is none, so drop.
  • At $12$ on $L_1$, the next key is $20 \ge 15$, so drop.
  • At $12$ on $L_0$, the next key is $15$. It is not $< 15$, so stop.

    • The answer is next of the current node, which is $15$. The search made 2 drops and 1 move right, and it skipped $3, 5, 8$ entirely.

    def find(self, x):
    u, r = self.sentinel, self.height
    while r >= 0:
        while u.next[r] is not None and u.next[r].key < x:
            u = u.next[r]          # move right
        r -= 1                     # drop down
    return u.next[0].key if u.next[0] else None

    add(x) records the predecessor $u_r$ at each level during this same search. It then picks a random height for the new node and splices it in after each recorded predecessor. remove(x) finds the same predecessors and unlinks the node at each level where it appears.

    Problem-solving application: why $O(\log n)$?

    Claim. The expected search length is $O(\log n)$.

    Analysis. Trace the search path backward from the target at $L_0$. At each step, the path came either from the left (a move right) or from above (a drop). Each node on the path was promoted to the current level with probability $1/2$. If it was promoted, the path went up. Otherwise it went left. So the backward walk is a sequence of fair coin flips. It stops when it reaches the top level $\approx \log_2 n$.

    The expected number of flips needed to get $\log_2 n$ "ups" is $2\log_2 n$. Expected left moves $\approx \log_2 n$, and expected drops $\approx \log_2 n$. So

    $$E[\text{path length}] \le 2\log_2 n + O(1) = O(\log n).$$

    The same bound holds for add and remove, since each does one search plus $O(h(u))$ pointer updates, and $E[h(u)] = 2$.

    Practice. For $n = 1{,}000{,}000$, estimate the search cost. $\log_2 n \approx 20$, so about $40$ steps instead of up to $10^6$ in a plain linked list.

    The bound is expected, not worst-case. An unlucky coin sequence can give a poor skiplist, but the probability of this shrinks rapidly with $n$.
