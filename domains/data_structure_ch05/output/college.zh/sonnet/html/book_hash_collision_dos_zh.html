Concept Book: Hash Collision Dos

收益(Payoff)

终点:为什么哈希碰撞拒绝服务是自然的收束

哈希表的平均性能建立在一个假设上:键被均匀地散列到 $m$ 个桶中。在此假设下,插入 $n$ 个键的期望总代价为 $O(n)$。哈希碰撞拒绝服务(hash_collision_dos) 恰好攻击这一假设:攻击者选择一批键,使它们全部落入同一个桶,于是每次插入都要遍历长度不断增长的链表,总代价变为

$$ \sum_{i=1}^{n} i = \frac{n(n+1)}{2} = \Theta(n^2). $$

这就是它作为本书终点的原因:它把前面所学的每一个概念(散列函数、负载因子、均摊分析、最坏情况与期望情况的区别)放在同一个问题里检验。它也说明,一个"平均情况下很快"的算法,在对手面前可能很脆弱。

工作示例:量化攻击的代价

设服务器每秒可完成 $10^8$ 次基本比较。一个请求携带 $n = 10^5$ 个参数名,这是常见 Web 框架会解析的规模。

  • 正常情况:约 $n = 10^5$ 次操作,耗时约 $1$ 毫秒。
  • 全部碰撞:约 $\dfrac{n^2}{2} = 5\times 10^{9}$ 次比较,耗时约 $50$ 秒。

    • 单个请求就能占满一个 CPU 核心约一分钟,放大倍数约为 $5\times10^{4}$。攻击者只需很小的带宽,就能拖垮服务。

    与各应用领域的联系

    本节没有列出具体的应用领域,因此下面给出该概念通常延伸到的三个方向。它们是我补充的示例,并非题目指定。

  • Web 服务与协议解析:表单参数、JSON 对象键、HTTP 头都被存入哈希表。防御方法是限制请求大小和键的数量。
  • 语言运行时与标准库:现代运行时(如 Python 和 Java)采用带密钥的散列函数(SipHash)或在桶过长时转为平衡树。这相当于把最坏情况从 $\Theta(n^2)$ 降到 $O(n\log n)$。
  • 通用散列与随机化算法:从全域散列族 $\mathcal H$ 中随机抽取 $h$,使得对任意 $x\ne y$,
    • $$ \Pr_{h\in\mathcal H}\big[h(x)=h(y)\big]\le \frac1m . $$

    这时攻击者事先不知道 $h$,无法构造碰撞,期望性能的保证在对手面前依然成立。
