哈希函数

定义。 哈希表是一个长度为 $m$(即 $\text{length}(t)=m$)的数组 $t$。哈希函数是一个映射

$$h: U \to \{0,1,\dots,m-1\},$$

它把键 $x\in U$(键的全集)变成数组下标,表示 $x$ 应存放在 $t[h(x)]$。好的哈希函数应满足三条要求:

  • 确定性:同一个键每次得到相同的下标。
  • 高效:计算时间为 $O(1)$(对定长键)。
  • 均匀性:各个下标被选中的概率大致相等,以减少冲突。

    • 由于 $|U|\gg m$,由鸽巢原理可知,必有不同的键映射到同一下标,这称为冲突。哈希函数的目标不是消除冲突,而是让冲突尽量少。

    常用构造:除法哈希。 若键是非负整数 $k$,取

    $$h(k)=k \bmod m.$$

    $m$ 最好选素数,并避开接近 $2^p$ 的值。若 $m=2^p$,则 $h(k)$ 只取决于 $k$ 的低 $p$ 位,高位信息被浪费。

    例题。 设 $m=7$,依次插入键 $50,\ 700,\ 76,\ 85,\ 92$。

    | 键 $k$ | 计算 | $h(k)$ | |---|---|---| | 50 | $50 = 7\cdot7+1$ | 1 | | 700 | $700=7\cdot100+0$ | 0 | | 76 | $76=7\cdot10+6$ | 6 | | 85 | $85=7\cdot12+1$ | 1 | | 92 | $92=7\cdot13+1$ | 1 |

    键 $50, 85, 92$ 都落在下标 1,发生冲突,需要用链地址法或开放寻址法处理。

    字符串键。 先把字符串转成整数,再取模。常用多项式哈希:

    $$h(s)=\Big(\sum_{i=0}^{n-1} s_i\, b^{\,n-1-i}\Big)\bmod m,$$

    其中 $s_i$ 是第 $i$ 个字符的编码,$b$ 是基数(如 31)。用 Horner 法则可在 $O(n)$ 时间内算出:

    def hash_str(s, m, b=31):
    h = 0
    for ch in s:
        h = (h * b + ord(ch)) % m
    return h

print(hash_str("cat", 101))  # 99*961+97*31+116 = 98,... mod 101

    问题求解应用。 假设哈希函数满足简单均匀哈希假设:每个键等概率落入 $m$ 个位置中的任意一个,且彼此独立。那么向表中插入 $n$ 个键后,定义装载因子 $\alpha=n/m$。用链地址法时,每条链的期望长度为 $\alpha$,所以一次查找的期望代价是

    $$\Theta(1+\alpha).$$

    若 $n=O(m)$,则查找、插入、删除的平均时间都是 $O(1)$。

    练习: 一张表有 $m=1000$ 个槽位,要存 $n=5000$ 个键。此时 $\alpha=5$,平均每次查找约需比较 $1+\alpha=6$ 次。若要把 $\alpha$ 降到 $0.5$ 以下,表至少要扩容到 $m>10000$。这正是动态哈希表在 $\alpha$ 过大时重新哈希(rehash)的原因。

    小结。 哈希函数把任意键压缩成有限范围内的下标。它的质量决定冲突的多少,进而决定哈希表能否达到平均 $O(1)$ 的性能。
