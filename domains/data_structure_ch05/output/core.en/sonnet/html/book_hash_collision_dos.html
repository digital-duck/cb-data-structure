Concept Book: Hash Collision Dos

Data Structure Ch05 · Generated by SPL

Payoff

A hash function $h : \mathcal{U} \to \{0, 1, \ldots, m-1\}$ is designed so that keys distribute uniformly across $m$ buckets, yielding expected $O(1)$ lookup time in a hash table. The security assumption embedded in this guarantee is subtle: it holds only when an adversary cannot predict or control which keys are inserted. Hash-collision denial of service (hash-collision DoS) is the attack that invalidates this assumption. By crafting a set of keys $K = \{k_1, k_2, \ldots, k_n\}$ such that $h(k_i) = h(k_j)$ for all $i \neq j$, an attacker collapses every insertion into a single bucket, degrading lookup from $O(1)$ to $O(n)$ and turning a web server's request parser, a compiler's symbol table, or a database's query cache into a CPU-exhaustion sink.

Worked example. Suppose a server uses the polynomial rolling hash $h(s) = \left(\sum_{i=0}^{\ell-1} s_i \cdot b^i\right) \bmod m$ with $b = 31$ and $m = 2^{16}$. Because $m$ is a power of two, the hash depends only on the low-order bits of the weighted sum. An attacker who knows $b$ and $m$ solves the linear congruence $b^i \equiv b^j \pmod{m}$ to find character substitutions that preserve $h$. Generating $n = 10{,}000$ such colliding strings and submitting them as HTTP POST field names causes the server's form-parser to perform $\Theta(n^2)$ comparisons — roughly $10^8$ string operations — per request, saturating a core within seconds.

Key theorem (Birthday complexity of forced collision). For a uniformly random hash function with range $m$, the expected number of distinct inputs needed to guarantee at least one collision is $\Theta(\sqrt{m})$. However, against a deterministic hash function known to the attacker, collisions can be constructed in time $O(m)$ by solving the preimage equation, rendering the birthday bound irrelevant: adversarial collision cost drops from $\Omega(\sqrt{m})$ to $O(\text{poly}(\log m))$ under algebraic attack.

This endpoint is natural because the entire chain of prior concepts — modular arithmetic, collision resistance, load-factor analysis, and algorithmic complexity — converges here into a single exploitable failure mode. Understanding hash-collision DoS means understanding precisely where and why each mathematical guarantee breaks down under adversarial input.

from sympy import symbols, Mod, solve

b, m_val = 31, 2**16
# Find two single-character strings with equal hash contribution
i, j = symbols('i j', integer=True, positive=True)
# Characters c1, c2 such that c1*b ≡ c2*b (mod m)  =>  (c1-c2)*b ≡ 0 (mod m)
c = symbols('c', integer=True)
solutions = solve(Mod(c * b, m_val), c)
print("Zero-delta characters (mod 2^16):", solutions[:5])
