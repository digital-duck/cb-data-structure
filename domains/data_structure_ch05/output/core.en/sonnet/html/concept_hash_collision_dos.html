Hash Collision Dos

Definition. A hash collision occurs when two distinct keys $k_1 \neq k_2$ satisfy $h(k_1) = h(k_2)$ for a hash function $h : U \to \{0, 1, \ldots, m-1\}$. Under chaining, a hash table resolves collisions by storing all colliding keys in a linked list at the same bucket. A Hash Collision Denial-of-Service (DoS) attack exploits this by supplying an adversarially chosen input set $S$ in which every element hashes to the same bucket, forcing every insertion and lookup to traverse a list of length $|S|$ rather than $O(1)$. The result is that $n$ operations degrade from expected $\Theta(n)$ total time to worst-case $\Theta(n^2)$, saturating server resources.

Worked Example. Suppose $h(k) = k \bmod 8$ and an attacker submits the keys $S = \{0, 8, 16, 24, 32, 40, 48, 56\}$. Every element satisfies $h(k) \equiv 0 \pmod{8}$, so all eight keys collide into bucket 0. A lookup for key $56$ must traverse all eight list nodes. With $n = 8$ such operations, the server performs $1 + 2 + \cdots + 8 = 36 = \Theta(n^2)$ comparisons rather than the $\Theta(n)$ expected under a uniform distribution.

Key Theorem (Load Factor and Worst-Case Cost). Let $T$ be a chained hash table with $m$ buckets storing $n$ keys, and define the load factor $\alpha = n/m$. Under a uniform independent hashing assumption, the expected search time is $\Theta(1 + \alpha)$. However, if the hash function $h$ is deterministic and publicly known, an adversary can always construct a set $S \subseteq U$ with $|S| = n$ such that all keys map to one bucket, yielding worst-case search time $\Theta(n)$ per operation. The standard defence is universal hashing: choose $h$ uniformly at random from a family $\mathcal{H}$ satisfying $\Pr_{h \in \mathcal{H}}[h(k_1) = h(k_2)] \leq 1/m$ for all $k_1 \neq k_2$. This guarantee holds regardless of adversarial input, bounding expected chain length at $1 + \alpha$.

Lab Cell (SymPy / Python).

from collections import defaultdict
import random, time

def deterministic_hash(k, m=8):
    return k % m

def universal_hash(k, m, a, b, p=1_000_003):
    return ((a * k + b) % p) % m

m = 8
attack_keys = list(range(0, 8 * m, m))   # all collide under deterministic_hash

# Deterministic: measure bucket distribution
det_table = defaultdict(list)
for k in attack_keys:
    det_table[deterministic_hash(k, m)].append(k)
print("Deterministic max chain:", max(len(v) for v in det_table.values()))

# Universal: choose random a, b
a, b = random.randint(1, 999), random.randint(0, 999)
univ_table = defaultdict(list)
for k in attack_keys:
    univ_table[universal_hash(k, m, a, b)].append(k)
print("Universal max chain:", max(len(v) for v in univ_table.values()))

Running this cell will show the deterministic table concentrating all eight keys in one bucket (chain length 8), while the universal hash distributes them more evenly, illustrating the practical defence against Hash Collision DoS.
