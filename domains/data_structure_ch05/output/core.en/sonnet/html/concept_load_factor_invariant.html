Load Factor Invariant

Definition. Let $T$ be a hash table with capacity $m$ (the number of available slots) and $n$ currently stored entries. The load factor of $T$ is the ratio

$$\alpha = \frac{n}{m}.$$

The load factor invariant is the guarantee maintained by a dynamic hash table implementation that $\alpha$ remains bounded within a fixed interval $[\alpha_{\min}, \alpha_{\max}]$ at the conclusion of every insertion or deletion operation. Typical implementations enforce $\alpha \leq 0.75$ for open-addressing schemes, with a lower bound such as $\alpha \geq 0.25$ enforced after deletions to prevent excessive memory waste.

Worked Example. Suppose a hash table is initialized with capacity $m = 8$ and $\alpha_{\max} = 0.75$. The threshold for rehashing is $\lfloor 0.75 \times 8 \rfloor = 6$ entries. As elements are inserted:

| Operation | $n$ | $m$ | $\alpha$ | Action | |-----------|-----|-----|----------|--------| | Insert 5 items | 5 | 8 | 0.625 | none | | Insert 6th item | 6 | 8 | 0.750 | none | | Insert 7th item | 7 | 8 | 0.875 | rehash to $m = 16$ |

After rehashing, $\alpha = 7/16 = 0.4375$, restoring the invariant.

Key Theorem (Amortized Cost of Rehashing). If a hash table doubles its capacity whenever $\alpha$ exceeds $\alpha_{\max}$, then the amortized cost per insertion is $O(1)$.

Proof sketch. Let $n_0$ be the number of entries immediately after the last rehash. To trigger the next rehash, at least $n_0$ additional insertions must occur (since capacity doubled to $2m$, so the threshold is $2\alpha_{\max} m = 2n_0$). The rehash copies at most $2n_0$ entries, distributing a cost of $O(n_0)$ across $n_0$ insertions, yielding $O(1)$ amortized cost per operation. $\square$

This argument is an instance of the potential method: defining the potential $\Phi = 2n - m$ ensures each insertion contributes a constant amount toward the eventual rehash cost.

Lab Cell (SymPy).

from sympy import symbols, solve, Rational

n, m = symbols('n m', positive=True)
alpha_max = Rational(3, 4)

# Find the minimum capacity m such that inserting one more item
# after n items does not exceed alpha_max
threshold = solve(n / m - alpha_max, m)
print("Rehash threshold m =", threshold)  # [4*n/3]

# Verify amortized invariant: entries needed before next rehash
n0 = 7  # entries after rehash to capacity 16
print(f"Entries at rehash trigger: {int(alpha_max * 16)}")  # 12
print(f"Insertions before next rehash: {int(alpha_max * 16) - n0}")  # 5

Running this cell confirms that after rehashing to $m = 16$ with $n = 7$, five more insertions are needed before the invariant is next threatened, consistent with the $O(1)$ amortized bound.
