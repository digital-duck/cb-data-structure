Concept Book: Unbalanced Bst Performance

Data Structure Ch06 · Generated by SPL

Payoff

Everything in this book has led to one result: a plain binary search tree (BST) offers no guarantee about its shape, so its performance depends entirely on the order in which keys arrive.

What the analysis achieves. Search, insertion, and deletion each cost $O(h)$, where $h$ is the tree's height. For $n$ keys, $h$ can be anywhere in the range

$$\lfloor \log_2 n \rfloor \le h \le n-1.$$

The lower bound is reached by a perfectly full tree. The upper bound is reached when keys arrive already sorted, because each new key becomes the right child of the previous one and the tree becomes a linked list. Then a search costs $\Theta(n)$, and building the whole tree costs

$$\sum_{i=1}^{n} i = \frac{n(n+1)}{2} = \Theta(n^2).$$

The analysis also gives a more hopeful average. If the keys are inserted in uniformly random order, the expected depth of a node is $2\ln n + O(1) \approx 1.39\log_2 n$. So the average case is $O(\log n)$, but the worst case is $\Theta(n)$. A guarantee that depends on the input's order is not something you can build a system on.

This is the natural endpoint because it turns a vague worry into a precise question. The cost is governed by $h$, and $h$ is not controlled. Any fix has to control $h$ directly.

Worked check. Insert $1,2,3,4,5$ in that order. The height is $4$, and finding $5$ takes $5$ comparisons. Insert $3,2,4,1,5$ instead and the height is $2$, so finding any key takes at most $3$ comparisons. The keys are the same and only their order changed, yet the cost differs by a factor that grows without bound as $n$ grows. For $n = 10^6$, the worst case needs about $10^6$ comparisons per search, while a balanced tree needs about $20$.

Connection to tree balancing strategies. The analysis tells you what a balancing strategy has to achieve and which tools can achieve it.

  • Goal. Keep $h = O(\log n)$ after every update, so that all operations cost $O(\log n)$ in the worst case.
  • Rotations. A rotation changes the shape of a subtree while preserving the in-order key sequence. This means it can repair height without breaking the BST property. Each rotation takes $O(1)$ time.
  • Invariants. AVL trees bound the height difference of sibling subtrees to at most $1$, which gives $h \le 1.44\log_2 n$. Red-black trees use color rules to ensure the longest root-to-leaf path is at most twice the shortest, which gives $h \le 2\log_2(n+1)$.
  • Alternatives. Randomization (treaps) and amortized restructuring (splay trees) get the same logarithmic behavior in expectation or on average, without strict height rules.

    • Each strategy is a different answer to the problem you can now state exactly: how do you keep $h$ small while paying little for each update?

    Where to go next. Pick one strategy and study it in depth. AVL trees are the most direct starting point. You can derive the height bound from the Fibonacci-like recurrence $N(h) = N(h-1) + N(h-2) + 1$ for the minimum number of nodes in a tree of height $h$. Then work out the four rotation cases that restore balance after an insertion. Try building an AVL tree from the sorted sequence $1,\dots,7$ and watch the degenerate list become a perfect tree.
