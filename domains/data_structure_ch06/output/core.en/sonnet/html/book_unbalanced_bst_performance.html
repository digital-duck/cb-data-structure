Concept Book: Unbalanced Bst Performance

Data Structure Ch06 · Generated by SPL

Payoff

A binary search tree achieves its advertised $O(\log n)$ search time only when the tree is balanced — that is, when every node's left and right subtrees differ in height by at most a small constant. The concept of unbalanced BST performance makes this dependency precise and quantitative, and it is the natural endpoint of the chapter because it converts an intuition ("a lopsided tree is slow") into a theorem with an exact cost function.

Definition. Let $T$ be a binary search tree on $n$ keys. The height $h(T)$ is the length of the longest root-to-leaf path. The worst-case cost of a search, insertion, or deletion in $T$ is $\Theta(h(T))$. When keys are inserted in sorted order, $T$ degenerates into a right-skewed chain and $h(T) = n - 1$, giving $\Theta(n)$ per operation.

Worked example. Insert the keys $1, 2, 3, 4, 5$ in increasing order into an empty BST. At each step the new key is always the largest, so it becomes the rightmost child. The resulting tree is a linked list of height $4$. A search for key $5$ traverses all five nodes, whereas in a balanced tree of the same size — height $\lfloor \log_2 5 \rfloor = 2$ — the same search visits at most three nodes. The ratio $4/2 = 2$ here becomes arbitrarily large as $n \to \infty$: sorted insertion degrades search time by a factor of $\Theta(n / \log n)$.

Key theorem (height lower and upper bounds). For any BST on $n$ nodes, $\lfloor \log_2 n \rfloor \leq h(T) \leq n - 1$. The lower bound is achieved by a complete binary tree; the upper bound by a degenerate chain. Any algorithm that maintains $h(T) = O(\log n)$ therefore guarantees $O(\log n)$ worst-case operations.

$$\lfloor \log_2 n \rfloor \;\leq\; h(T) \;\leq\; n - 1$$

Connection to tree balancing strategies. The theorem above is not merely a warning — it is a design specification. Every balancing strategy (AVL trees, red-black trees, B-trees, treaps) exists precisely to enforce $h(T) = O(\log n)$ as an invariant, and each makes a different trade-off between the cost of rebalancing during insertion and deletion versus the cost of search. Understanding why imbalance is harmful — and quantifying the degradation as $\Theta(h(T))$ — is the prerequisite for evaluating any such strategy on its own terms.
