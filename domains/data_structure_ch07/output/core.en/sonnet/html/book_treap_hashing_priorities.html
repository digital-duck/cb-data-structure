Concept Book: Treap Hashing Priorities

Data Structure Ch07 · Generated by SPL

Payoff

Throughout this text we have built, layer by layer, a vocabulary for reasoning about randomized search structures. We began with the binary search tree and its worst-case fragility, introduced heaps and their priority discipline, and then fused them into the treap—a structure whose shape is governed jointly by a key order and a randomly drawn priority. The concept of treap hashing priorities is the natural endpoint of that journey: rather than drawing priorities from an external source of randomness, we derive them deterministically from the keys themselves via a hash function. The result is a data structure whose balance guarantees are probabilistic yet whose behavior is entirely reproducible.

What the concept achieves. Let $h : \mathcal{K} \to [0,1)$ be a hash function whose outputs are uniformly distributed over the unit interval (in practice, a cryptographic hash rescaled). Given a set of keys $K = \{k_1, k_2, \ldots, k_n\} \subseteq \mathcal{K}$, the treap with hashing priorities is the unique binary tree $T$ satisfying

$$k_i \in \text{left-subtree}(k_j) \iff k_i < k_j \quad (\text{BST property})$$

and

$$h(k_i) \geq h(k_j) \text{ whenever } k_j \text{ is the parent of } k_i \quad (\text{max-heap on priorities}).$$

Because $h$ behaves as a uniform random permutation on any finite key set (with overwhelming probability for collision-resistant $h$), the expected depth of any node is $O(\log n)$, and the expected cost of search, insertion, and deletion is $O(\log n)$ — identical to the guarantees of a classical randomized treap, but without storing or communicating priority values.

Worked example. Take $\mathcal{K} = \{$apple, mango, plum$\}$ with SHA-256 priorities (truncated to four hex digits for illustration):

| Key | $h(\text{key})$ | Role in treap | |-----|----------------|---------------| | plum | $\texttt{0xf3a1}$ | root (highest priority) | | mango | $\texttt{0x9c4d}$ | right child of root | | apple | $\texttt{0x2b7e}$ | left child of root |

The BST ordering apple $<$ mango $<$ plum is preserved at every level, while the heap ordering on $h$ fixes the unique tree shape. Any peer who applies the same hash function reconstructs exactly this tree from the key set alone—no coordination required.

Key theorem (structural uniqueness). For any injective function $h$ and any key set $K$, the treap with priorities $\{h(k) : k \in K\}$ is the unique binary search tree on $K$ whose in-order traversal is sorted and whose root-to-leaf paths are decreasing in priority. Equivalently, it is the Cartesian tree of the sequence obtained by sorting $K$ and reading off $h$-values. This uniqueness is what distinguishes hashing priorities from random priorities: two independent processes building the same logical set converge to identical memory layouts.

Lab cell.

import hashlib, struct
from sympy import symbols

def hash_priority(key: str) -> float:
    digest = hashlib.sha256(key.encode()).digest()
    return struct.unpack(">Q", digest[:8])[0] / (2**64)

keys = ["apple", "mango", "plum"]
priorities = {k: hash_priority(k) for k in keys}
root = max(priorities, key=priorities.get)
print(f"Root (highest priority): {root}")
print({k: f"{v:.6f}" for k, v in priorities.items()})

Running this cell makes the uniqueness theorem tangible: regardless of insertion order, the same root emerges every time.

Invitation. Treap hashing priorities sit at the crossroads of randomized algorithms, cryptographic hashing, and distributed systems. One of the most striking downstream consequences is consistent hashing for distributed key-value stores: the same structural-uniqueness property that fixes a single treap across processes can be scaled to assign keys to servers in a ring topology with minimal reshuffling under node arrivals and departures.
