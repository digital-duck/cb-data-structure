Treap Add

Definition. A treap is a randomized binary search tree in which each node $x$ stores a key $x.\mathrm{key}$ and a randomly assigned priority $x.\mathrm{pri} \in \mathbb{R}$. The structure satisfies two invariants simultaneously: the binary search tree (BST) property on keys, and the max-heap property on priorities. The treap-add operation inserts a new key $k$ into a treap $T$ while preserving both invariants. Each new node is assigned a uniformly random priority $p \sim \mathrm{Uniform}(0,1)$, and the tree is rebalanced via rotations.

The single rotation primitive used in this section is the left rotation at node $x$ with right child $y$:

$$\text{left-rotate}(x): \quad x.\mathrm{right} \leftarrow y.\mathrm{left},\quad y.\mathrm{left} \leftarrow x.$$

This replaces $x$ with $y$ as the subtree root while preserving BST order. When the newly inserted node lands in a left subtree instead, the symmetric right rotation applies by mirror image; it is not a new primitive but the same operation reflected.

Worked Example. Suppose $T$ contains keys $\{3, 7, 11\}$ with priorities $\{0.80, 0.95, 0.60\}$, so node $7$ is the root. We insert $k = 9$ with randomly drawn priority $p = 0.97$.

  • Descend by BST order: $9 > 7$, so $9$ becomes the right child of $7$.
  • Check the heap property: $0.97 > 0.95$, so node $9$ must rise above node $7$.
  • Apply a left rotation at node $7$: node $9$ becomes the new root, with $7$ as its left child and $11$ as its right child.
  • Node $3$ remains the left child of $7$. Both invariants hold.

    • Key Theorem (Expected Height). Because priorities are chosen independently and uniformly at random, the expected depth of any key $k$ in an $n$-node treap equals $O(\log n)$. More precisely, the expected number of comparisons during an insertion is

    $$\mathbb{E}[\text{comparisons}] = 2H_n - 1 \leq 2\ln n + 1,$$

    where $H_n = \sum_{i=1}^{n} \frac{1}{i}$ is the $n$-th harmonic number. Consequently, treap-add runs in $O(\log n)$ expected time with no worst-case-sensitive balancing logic.

    Lab Cell.

    from sympy import symbols, harmonic, ln, simplify

n = symbols('n', positive=True, integer=True)
expected_comparisons = 2 * harmonic(n) - 1

# Numerical check for n = 16
val = expected_comparisons.subs(n, 16)
print(f"Expected comparisons (n=16): {float(val):.4f}")   # ≈ 5.77
print(f"2·ln(16) + 1 upper bound:    {2*float(ln(16))+1:.4f}")  # ≈ 6.55

    Running this cell confirms that the harmonic bound tracks closely with the logarithmic upper bound, illustrating why treaps are practical for general-purpose dynamic sets.
