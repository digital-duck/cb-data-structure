Concept Book: Weight Balanced Tree

Data Structure Ch08 · Generated by SPL

Payoff

A weight-balanced tree stores, at every node $v$, the size $s(v)$ of its subtree, and enforces one local rule: neither child may carry too large a share of the weight. With $s'(v)=s(v)+1$, the balance condition is

$$\alpha \le \frac{s'(\text{left}(v))}{s'(v)} \le 1-\alpha.$$

For $\alpha$ in a safe range (the classic result is $\alpha \le 1-\tfrac{1}{\sqrt 2}\approx 0.29$, with the Hirai–Yamamoto proof giving parameter choices such as $(\Delta,\Gamma)=(3,2)$), single and double rotations restore the invariant after each insertion or deletion. Because every step down the tree shrinks the subtree by a factor of at most $1-\alpha$, the height is bounded by

$$h \le \log_{1/(1-\alpha)}(n+1) = O(\log n).$$

Why this is the natural endpoint. Earlier structures in this book gave you ordered search, then height-based balance (such as AVL or red-black trees). The weight-balanced tree completes the picture by making size a first-class, maintained quantity. You get the same $O(\log n)$ search, insert, and delete as any balanced tree. You also get $O(\log n)$ rank and select operations for free, because the stored sizes already tell you how many keys lie to the left. Its balance also has an amortized property that height-balanced trees lack: after a rebalance at a node of size $s$, $\Omega(s)$ updates must occur beneath it before that node needs rebalancing again.

Worked example. Suppose a node has $s(v)=10$, so $s'(v)=11$. Its left child has size 1 and its right child has size 8. Then $s'(\text{left})=2$, and $2/11\approx 0.18<0.29$. The invariant fails, so a rotation is needed. Rotating the heavy right side upward shifts weight leftward and restores the ratio.

Connections to application domains. The listed applications section for this chapter is empty, so there are no named domains to map onto. The properties above point to three natural families, listed here as suggestions rather than as given applications:

  • Order-statistic queries: leaderboards, percentiles, and median maintenance rely on rank and select.
  • Functional and persistent data structures: weight-balanced trees are a standard choice for immutable sets and maps, such as Haskell's Data.Map and Data.Set. Their balance rule needs no stored color or height flags, and rebalancing touches only the path being rebuilt.
  • Parallel set operations: union, intersection, and difference can be done by splitting on a root key and recursing in parallel. This works because the balance is controlled by size.

    • Problem-solving takeaway. When a problem asks "what is the $k$th smallest?" or "how many keys are below $x$?", augment the tree with sizes and keep it balanced by weight.

    An invitation. Pick one family above and build it. A good first project is an order-statistic set supporting insert, delete, rank, and select. Implement the balance check from the formula above, then test it on sorted input, which breaks an unbalanced BST. Measure the height against $\log_{1/(1-\alpha)} n$ as you go.
