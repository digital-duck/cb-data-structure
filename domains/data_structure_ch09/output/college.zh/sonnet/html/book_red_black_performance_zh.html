红黑树性能的意义

红黑树(red-black tree)是一种自平衡二叉搜索树。它的所有性能保证都来自一个结论:含 $n$ 个内部结点的红黑树,高度 $h$ 满足

$$h \le 2\log_2(n+1).$$

简要论证。 红黑树满足两条性质:(1)红结点的子结点必为黑色;(2)从任一结点到其后代叶结点的所有路径含有相同数目的黑结点。设根的黑高为 $b$。由性质(1),任何一条根到叶的路径上,红结点数不超过黑结点数,因此 $h \le 2b$。由性质(2),前 $b$ 层都是满的,所以 $n \ge 2^b - 1$,即 $b \le \log_2(n+1)$。两式合并即得上界。

这就是红黑树成为这门课"自然终点"的原因。前面学过的二叉搜索树、旋转、着色规则和插入、删除的修复步骤,最终都服务于同一个目标:把最坏情况的查找、插入、删除代价稳定在

$$T(n) = O(\log n).$$

普通二叉搜索树在有序输入下会退化成链表,代价为 $O(n)$。红黑树则用最多 $O(1)$ 次旋转和 $O(\log n)$ 次重新着色换来了最坏情况保证。

工作示例

向空树依次插入 $1,2,3,\dots,10^6$。普通 BST 的高度是 $10^6$,一次查找最多要比较一百万次。红黑树的高度不超过

$$2\log_2(10^6+1)\approx 2\times 19.93 \approx 40,$$

所以最多比较约 40 次,差距约 $25000$ 倍。

应用领域

题目没有列出具体的应用领域,这里按红黑树的实际用途讲三类典型场景,每一类都直接依赖上面的 $O(\log n)$ 保证。

  • 语言标准库中的有序容器。 C++ 的 std::map、std::set 和 Java 的 TreeMap 通常用红黑树实现。有序遍历、范围查询、前驱和后继操作都继承了对数级的最坏情况代价。
  • 操作系统调度与内存管理。 Linux 的完全公平调度器(CFS)用红黑树按虚拟运行时间排序进程,每次取出最小键的代价为 $O(\log n)$。虚拟内存区域的管理同样用它做区间查找。
  • 计算几何与数据库索引。 扫描线算法需要在事件队列和状态结构里动态维护有序集合。红黑树让整个算法保持 $O(n\log n)$ 的总代价。

    • 练习:把理论用到问题上

    假设某调度器每秒要处理 $10^5$ 次"插入一个任务、取出最小任务"。请估计在 $n=10^6$ 个就绪任务时,红黑树方案的最坏比较次数,并与链表有序插入的 $O(n)$ 方案比较。你会发现前者每秒约 $10^5\times 40=4\times10^6$ 次比较,后者则可能达到 $10^{11}$ 量级。
