Concept Book: Red Black Performance

Data Structure Ch09 · Generated by SPL

Payoff

A red-black tree is a binary search tree augmented with a single bit of color information per node and four invariants that together guarantee the tree never becomes too unbalanced. The central performance result is clean and unconditional.

Theorem (Red-Black Performance Guarantee). Let $T$ be a red-black tree storing $n$ keys. Every search, insertion, and deletion executes in $O(\log n)$ worst-case time.

The proof hinges on a height bound. Define the black-height $\mathrm{bh}(v)$ of a node $v$ as the number of black nodes on any path from $v$ to a null leaf (not counting $v$ itself). The red-black invariants force every internal node with black-height $k$ to subtend at least $2^k - 1$ internal nodes, so $n \geq 2^{\mathrm{bh}(\text{root})} - 1$. Because no red node may have a red child, the longest root-to-leaf path alternates colors and has length at most $2\,\mathrm{bh}(\text{root})$. Combining these two facts yields

$$h(T) \leq 2\log_2(n+1),$$

so the height is $\Theta(\log n)$ and every pointer-following operation inherits that bound.

Worked Example. Suppose $n = 10^6$ keys are stored. Then $h(T) \leq 2\log_2(10^6 + 1) \approx 2 \times 19.93 \approx 39.9$, so at most 40 node comparisons suffice for any search—regardless of insertion order. An unbalanced BST built from sorted input would instead require up to $10^6$ comparisons.

The guarantee matters precisely because it is worst-case, not amortized. Systems that tolerate occasional slow operations (garbage collection pauses, lock contention spikes) behave poorly at tail latency even when the average is fast. Red-black trees eliminate that tail.

# Lab cell — verify the height bound empirically
from sympy import log, ceiling, symbols

n_val = 10**6
bound = 2 * ceiling(log(n_val + 1, 2))
print(f"Height bound for n={n_val:,}: {bound}")   # expects 40

n = symbols('n', positive=True)
print(f"Symbolic bound: {2*log(n+1, 2)}")

With $O(\log n)$ worst-case performance established, every application that requires ordered, dynamic data—database indexing, interval scheduling, memory allocators, language runtimes—gains a principled foundation.
