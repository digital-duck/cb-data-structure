Concept Book: Heapsort

Data Structure Ch10 · Generated by SPL

Payoff

Heapsort is the point where three earlier ideas, the binary heap, the sift-down repair, and in-place array manipulation, combine into one algorithm. Its guarantees are strong: it sorts $n$ keys in $\Theta(n \log n)$ time in the best, average, and worst cases, and it uses only $O(1)$ extra space.

Why it is the natural endpoint. Building a max-heap bottom-up takes $O(n)$ time. Each level $h$ contains at most $\lceil n/2^{h+1}\rceil$ nodes, and each of those nodes sifts down at most $h$ steps, so

$$T_{\text{build}}(n) \le \sum_{h=0}^{\lfloor \log_2 n\rfloor} \left\lceil \frac{n}{2^{h+1}} \right\rceil h = O\!\left(n\sum_{h\ge 0}\frac{h}{2^h}\right) = O(n).$$

The sort then repeats a simple step: swap the root with the last heap element, shrink the heap by one, and sift down. This costs $O(\log n)$ per step over $n-1$ steps, so the total is $T(n)=O(n)+O(n\log n)=\Theta(n\log n)$. Comparison sorting needs $\Omega(n\log n)$ comparisons in the worst case, because a decision tree with $n!$ leaves has height at least $\log_2(n!)=\Theta(n\log n)$. So heapsort is asymptotically optimal. Mergesort has the same time bound but needs $\Theta(n)$ extra space, and quicksort is faster in practice but can degrade to $\Theta(n^2)$. Heapsort has neither weakness.

Connection to the application domains. The ideas inside heapsort carry over to several settings.

  • Priority queues and scheduling. The sort's inner loop is the heap's extract-max operation. Operating systems use the same structure to pick the highest-priority task in $O(\log n)$ time, and discrete-event simulators use it to find the next event.
  • Selection and top-$k$ problems. You can stop after $k$ extractions. This finds the $k$ largest items in $O(n + k\log n)$ time without sorting everything. A bounded min-heap of size $k$ handles streaming data in $O(n\log k)$ time.
  • Graph algorithms. Dijkstra's shortest-path algorithm and Prim's minimum spanning tree algorithm both rely on a heap to choose the next vertex. With a binary heap they run in $O((V+E)\log V)$ time.
  • Embedded and memory-limited systems. The $O(1)$ extra-space guarantee and the predictable worst-case time make heapsort a good fit where memory is tight or real-time deadlines apply. Introsort, the hybrid used in many standard libraries, switches to heapsort when quicksort recursion gets too deep, which preserves a worst-case $O(n\log n)$ bound.

    • Problem-solving check. Suppose a server receives $10^7$ request latencies and needs only the 100 slowest. Fully sorting costs about $10^7\log_2 10^7 \approx 2.3\times10^8$ comparisons. A size-100 heap costs about $10^7\log_2 100\approx 6.6\times10^7$, which is roughly a 3.5-fold saving. Seeing which structure fits the question being asked is the main skill heapsort teaches.

    An invitation. Choose one application and implement it. Dijkstra's algorithm is a good candidate. Write it first with a plain array scan, which costs $O(V^2)$. Then replace the scan with a binary heap and measure the speedup on a sparse graph with $10^5$ vertices. You will see an algorithm you learned as a sorting method working as a general-purpose tool.
