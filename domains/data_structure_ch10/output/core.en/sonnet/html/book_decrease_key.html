Concept Book: Decrease Key

Data Structure Ch10 · Generated by SPL

Payoff

The journey through priority-queue theory reaches its natural summit with the decrease\_key operation. Every earlier concept—binary heaps, the heap-order invariant, sift-up and sift-down procedures—was, in a precise sense, preparation for this single primitive. Informally, decrease\_key answers the question: given that we already know an element's priority, how can we revise that priority downward without rebuilding the entire structure? Formally, for a min-heap $H$ storing pairs $(v, k)$, the operation

$$\texttt{decrease\_key}(H,\, v,\, k') \quad \text{where } k' < k_v$$

locates the node $v$ currently carrying key $k_v$, replaces $k_v$ with the strictly smaller value $k'$, and restores the heap-order invariant by propagating $v$ upward along its ancestral path. The invariant is violated at most along a single root-to-leaf path of length $\lfloor \log_2 n \rfloor$, so the worst-case cost is $O(\log n)$ comparisons and swaps.

Worked example. Consider the min-heap below (node label / key):

$$A/2,\quad B/5,\quad C/3,\quad D/9,\quad E/7$$

Call $\texttt{decrease\_key}(H, D, 1)$. Node $D$ now carries key $1$. Compare with its parent $B$ (key $5$): since $1 < 5$, swap. Compare the new position with $A$ (key $2$): since $1 < 2$, swap again. $D$ is now the root, and the heap-order invariant holds throughout. Exactly two comparisons sufficed—matching the $\lfloor \log_2 4 \rfloor = 2$ bound.

Theorem (Decrease-Key Complexity). In a binary min-heap of $n$ elements, $\texttt{decrease\_key}$ runs in $O(\log n)$ time. In a Fibonacci heap, amortised over any sequence of $m$ operations, the cost drops to $O(1)$, achieved by deferring structural consolidation.

Why it unlocks Dijkstra's algorithm. Dijkstra's shortest-path algorithm maintains a priority queue of tentative distances. Each time a shorter path to a vertex $v$ is discovered, the algorithm must revise $v$'s priority rather than insert a fresh copy—precisely a decrease\_key call. Without this operation, each relaxation step would require $O(n)$ time or duplicate entries; with it, and using a Fibonacci heap, the total runtime over a graph $G = (V, E)$ tightens to the landmark bound $O(|E| + |V| \log |V|)$, optimal for dense graphs.

# Lab cell — verify sift-up after decrease_key
import heapq

heap = [2, 5, 3, 9, 7]   # already a valid min-heap (stored as list)
heapq.heapify(heap)

# Simulate decrease_key: replace value 9 with 1
idx = heap.index(9)
heap[idx] = 1
# heapq does not expose sift-up directly; use the private method
heapq._siftdown(heap, 0, idx)   # sift-up toward index 0

print(heap)   # expected: [1, 2, 3, 5, 7] or equivalent valid heap
assert heap[0] == 1, "New minimum must be at root"

The elegance of decrease\_key is that it converts a static data structure into a dynamic one: the heap does not merely answer "what is the minimum?" but continuously adapts as new information arrives. This adaptability is the heartbeat of Dijkstra's algorithm—and it is waiting for you in the next chapter.
