Concept Book: Heapsort

Payoff

Heapsort stands at the confluence of two ideas developed throughout this text: the structural discipline of the binary heap and the algorithmic ambition of comparison-based sorting. Having internalized both, the reader now commands an algorithm that is simultaneously optimal in the worst case, in-place, and free of auxiliary storage—a combination no simpler method achieves.

What heapsort delivers. Given an array $A$ of $n$ comparable elements, heapsort produces a sorted permutation of $A$ in $\Theta(n \log n)$ time and $O(1)$ additional space. The first phase, heapification, establishes the max-heap invariant in $O(n)$ time by the telescoping-sum argument: $\sum_{h=0}^{\lfloor \log n \rfloor} \lceil n/2^{h+1} \rceil \cdot O(h) = O(n)$. The second phase, extraction, repeatedly swaps the root with the last unsorted element and sifts down, consuming $O(\log k)$ work at step $k$, so the total extraction cost is $\sum_{k=1}^{n} \lfloor \log k \rfloor \leq n \lfloor \log n \rfloor = O(n \log n)$. Together they yield the bound $T(n) = O(n)+ O(n \log n) = \Theta(n \log n)$.

Key theorem. By the decision-tree lower bound, any comparison-based sorting algorithm requires $\Omega(n \log n)$ comparisons in the worst case, since the $n!$ possible input permutations demand a tree of depth at least $\log_2(n!)=\Theta(n\log n)$ by Stirling's approximation. Heapsort meets this bound exactly; it is asymptotically optimal among all comparison sorts.

Worked example. Sort $A = [3, 1, 4, 1, 5]$. Heapify in place: after Floyd's procedure, $A = [5, 3, 4, 1, 1]$. Extract: swap $A[0] \leftrightarrow A[4]$, sift down on $[5-1]$ elements, giving $[4, 3, 1, 1 \mid 5]$. Continue until $A = [1, 1, 3, 4, 5]$.

Heapsort is not merely a terminus—it is a launchpad. Priority queues, built on the same heap invariant, underpin Dijkstra's shortest-path algorithm, event-driven simulation, and real-time scheduling. The $O(\log n)$ extract-maximum operation that drives heapsort's extraction phase is precisely the operation a scheduler invokes millions of times per second to select the highest-priority task. If you wish to see how a $\Theta(n \log n)$ idea shapes the microsecond decisions inside an operating-system kernel or a network router, turn to Chapter 9, where we build a live task scheduler from the heap upward.
