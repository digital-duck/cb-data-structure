Concept Book: Integer Sorting Via Indexing

Data Structure Ch11 · Generated by SPL

结语:收获

整数排序的索引法(integer sorting via indexing)是整本教材的自然终点。它把"比较"这一默认前提彻底抛开,让数据自己指出该去哪里。

它实现了什么

设待排序的 $n$ 个整数取值于 $\{0,1,\dots,k-1\}$。比较排序在最坏情况下有下界 $\Omega(n\log n)$,因为 $n$ 个元素有 $n!$ 种排列,决策树至少需要 $\log_2(n!)=\Theta(n\log n)$ 层。索引法不经过决策树,而是把"值"直接当作数组下标:

  • 计数:对每个 $x_i$,令 $C[x_i]\leftarrow C[x_i]+1$。
  • 前缀和:令 $C[v]\leftarrow \sum_{u\le v}C[u]$,此时 $C[v]$ 是不大于 $v$ 的元素个数,即 $v$ 的最后位置。
  • 倒序放置:从 $i=n$ 到 $1$,令 $C[x_i]\leftarrow C[x_i]-1$,并把 $x_i$ 写入 $B[C[x_i]]$。

    • 总代价为 $\Theta(n+k)$。当 $k=O(n)$ 时即为线性时间。倒序放置保证稳定性,即相等元素保持原有相对顺序。这正是它能作为基数排序子程序的关键。

    小例子:输入 $[2,5,3,0,2,3,0,3]$,$k=6$。计数得 $C=[2,0,2,3,0,1]$,前缀和得 $C=[2,2,4,7,7,8]$,放置后得 $[0,0,2,2,3,3,3,5]$。

    它之所以是终点,是因为前面各章的内容在这里汇合:数组随机访问、循环不变式、累加求和、稳定性、复杂度分析。同时它也说明了一个深刻的道理:下界取决于所允许的操作。比较模型禁止"用值做下标",一旦放开这一点,下界就不再适用。

    它通向哪里

    本书未指定具体应用领域,但这一思想可以在多个方向上延伸:

  • 基数排序:把 $d$ 位数逐位用稳定计数排序处理,总代价 $\Theta(d(n+k))$,可排序大整数、日期、字符串。
  • 直方图与统计:步骤 1 的 $C$ 本身就是频数分布,可直接用于图像处理与数据分析。
  • 数据库与索引:倒排索引、桶式分组都是"以值为地址"的同一思路。
  • 后缀数组构造:现代算法依赖基数排序对字符对排序,以获得线性时间。

    • 邀请

    不妨选择其中一个方向深入下去。例如,试着用计数排序作为子程序实现基数排序,并回答:在 $n=10^6$、整数范围为 $[0,2^{32})$ 时,选择什么样的进制 $k$ 能使 $d(n+k)$ 最小?亲手测量并与 $\Theta(n\log n)$ 的比较排序对照,你会真切体会到:改变问题的模型,就能改变问题的难度。
