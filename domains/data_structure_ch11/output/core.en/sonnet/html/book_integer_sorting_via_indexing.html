Concept Book: Integer Sorting Via Indexing

Data Structure Ch11 · Generated by SPL

Payoff

Every sorting algorithm studied in a first course — merge sort, quicksort, heapsort — operates by comparison: it asks "is $a < b$?" and rearranges elements accordingly, paying $\Omega(n \log n)$ comparisons in the worst case. Integer sorting via indexing breaks through that barrier by exploiting an arithmetic property that comparisons cannot see: when the keys are integers drawn from a bounded universe $\mathcal{U} = \{0, 1, \ldots, u-1\}$, each key is simultaneously a value and an address. Rather than discovering order through pairwise tests, the algorithm writes each element directly to the cell whose index equals the element's key, then reads the cells in address order to recover a sorted sequence.

Definition. Let $A = (a_1, a_2, \ldots, a_n)$ be a sequence of integers with $a_i \in \mathcal{U}$ for all $i$. Integer sorting via indexing allocates an auxiliary array $C$ of length $u$ initialised to zero, increments $C[a_i]$ for each $i \in \{1,\ldots,n\}$, and reconstructs the sorted output by emitting key $k$ exactly $C[k]$ times for $k = 0, 1, \ldots, u-1$ in turn. This is the counting sort schema; the index $k$ functions simultaneously as a histogram bin and a rank certificate.

Worked example. Suppose $A = (3, 1, 4, 1, 5, 9, 2, 6)$ with $\mathcal{U} = \{0,\ldots,9\}$. After the counting pass, the non-zero entries of $C$ are $C[1]=2,\, C[2]=1,\, C[3]=1,\, C[4]=1,\, C[5]=1,\, C[6]=1,\, C[9]=1$. Reading left to right yields $1,1,2,3,4,5,6,9$ — correctly sorted in a single linear scan of $C$.

Theorem (linear time). Integer sorting via indexing runs in $\Theta(n + u)$ time and $\Theta(u)$ auxiliary space. When $u = O(n)$, this is $\Theta(n)$, strictly below the $\Omega(n \log n)$ comparison-based lower bound.

Proof sketch. The counting pass visits each of the $n$ elements once; the reconstruction pass visits each of the $u$ cells once. No comparisons are performed, so the information-theoretic lower bound on comparison sorts does not apply. $\square$

# Lab cell — verify with SymPy/Python
from sympy import Array

def index_sort(seq, u):
    C = [0] * u
    for x in seq:
        C[x] += 1
    return [k for k, cnt in enumerate(C) for _ in range(cnt)]

A = [3, 1, 4, 1, 5, 9, 2, 6]
print(index_sort(A, u=10))   # [1, 1, 2, 3, 4, 5, 6, 9]

Integer sorting via indexing is the natural endpoint of this book's arc because it unifies the arithmetic of indices, the combinatorics of histograms, and the asymptotic analysis of algorithms into a single, elegant $O(n)$ procedure. To see how deeply this idea ramifies, consider pressing into radix sort, where iterated index-based passes sort multi-digit integers digit by digit, achieving $O(d \cdot n)$ time for $d$-digit keys — an industrial-strength technique underlying the packet-classification engines inside every internet router. Choose one such extension and follow its proof to its conclusion; the reward is a class of algorithms that are, in a precise mathematical sense, as fast as sorting can possibly be.
