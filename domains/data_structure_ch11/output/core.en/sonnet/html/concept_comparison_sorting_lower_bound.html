Comparison Sorting Lower Bound

Definition. A comparison-based sorting algorithm determines the sorted order of $n$ elements solely through pairwise comparisons of the form "is $a_i \leq a_j$?" Each comparison yields one bit of information (yes or no), and the algorithm may branch on that result. The comparison sorting lower bound states that any such algorithm must perform at least $\Omega(n \log n)$ comparisons in the worst case to sort $n$ distinct elements.

Decision Tree Model. Every comparison sort can be modeled as a binary decision tree: each internal node represents a comparison, each edge represents an outcome, and each leaf represents a permutation of the input that the algorithm has determined to be the sorted order. Because there are $n!$ possible input permutations, the decision tree must have at least $n!$ leaves. A binary tree of height $h$ has at most $2^h$ leaves, so we require

$$2^h \geq n! \implies h \geq \log_2(n!).$$

Applying Stirling's approximation, $\log_2(n!) = \Theta(n \log n)$, which establishes the lower bound.

Worked Example. Consider $n = 3$ elements $\{a, b, c\}$. There are $3! = 6$ possible orderings. A decision tree sorting three elements needs at least $\lceil \log_2 6 \rceil = 3$ comparisons in the worst case. Algorithms such as insertion sort on three elements indeed require up to 3 comparisons: compare $a$ vs.\ $b$, then introduce $c$ with at most two further comparisons, confirming the bound is tight.

Key Theorem. (Information-theoretic lower bound) Any deterministic comparison-based sorting algorithm requires at least $\lceil \log_2(n!) \rceil \geq n\log_2 n - n\log_2 e$ comparisons in the worst case. Algorithms such as merge sort and heapsort achieve $O(n \log n)$ comparisons, showing the bound is asymptotically tight.

Lab Cell (SymPy).

from sympy import factorial, log, ceiling, symbols, N

n = symbols('n', positive=True, integer=True)

for size in [4, 8, 16, 32]:
    lower = ceiling(log(factorial(size), 2))
    print(f"n={size:3d}:  ceil(log2({size}!)) = {lower}  "
          f"≈ n·log2(n) = {N(size * log(size, 2), 4)}")

Running this cell confirms that $\lceil \log_2(n!) \rceil$ tracks $n\log_2 n$ closely, and that no comparison sort can escape this fundamental information-theoretic constraint.
