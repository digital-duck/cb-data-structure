Comparison Tree

Definition. A comparison tree is a rooted binary tree that models the execution of a comparison-based algorithm on an ordered set. Each internal node is labelled with a comparison $a_i \leq a_j$; the left subtree is followed when the comparison evaluates to true and the right subtree when it evaluates to false. Each leaf is labelled with a distinct outcome—typically a permutation of the input or a search result. For an input of size $n$, the tree has at most $n!$ leaves (when modelling sorting) or $n+1$ leaves (when modelling binary search). The depth of a leaf equals the number of comparisons performed along the path from the root to that leaf; the height of the tree therefore equals the worst-case comparison count of the algorithm.

Worked Example. Consider insertion sort on three distinct elements $\{a, b, c\}$. The algorithm first asks $a \leq b$. If true, it asks $b \leq c$; if that is also true, the sorted order is $a, b, c$ (a leaf at depth 2). If $b \leq c$ is false, it asks $a \leq c$, yielding either $a, c, b$ or $c, a, b$ (leaves at depth 3). The false branch of the root similarly produces three leaves. Altogether the tree has six leaves—one for each of the $3! = 6$ permutations—and height 3, matching the worst-case comparison count of insertion sort for $n = 3$.

Key Theorem (Information-Theoretic Lower Bound). Any comparison-based sorting algorithm requires at least $\lceil \log_2(n!) \rceil$ comparisons in the worst case.

Proof sketch. A binary tree of height $h$ has at most $2^h$ leaves. Since a correct sorting algorithm must distinguish all $n!$ permutations, the tree must have at least $n!$ leaves, giving $2^h \geq n!$, hence $h \geq \log_2(n!)$. Because $h$ is an integer, $h \geq \lceil \log_2(n!) \rceil$. By Stirling's approximation, $\log_2(n!) \approx n\log_2 n - n\log_2 e$, so no comparison sort can beat $\Omega(n \log n)$.

Lab Cell.

from sympy import factorial, ceiling, log, symbols, simplify

n = symbols('n', positive=True, integer=True)

# Exact lower bound for small n
for size in range(2, 9):
    bound = ceiling(log(factorial(size), 2))
    print(f"n={size}: ceil(log2({size}!)) = {bound} comparisons")

Running this cell prints the minimum worst-case comparisons for $n = 2, \ldots, 8$, confirming that merge sort (which achieves $\lceil n \log_2 n \rceil$ in the worst case) is asymptotically optimal.
