Stable Sorting

Definition. A sorting algorithm is called stable if it preserves the relative order of elements that compare as equal. Formally, given a sequence $A = (a_1, a_2, \ldots, a_n)$ with a comparison key $k : A \to K$ where $K$ is a totally ordered set, a stable sort produces a permutation $\sigma$ such that:

$$k(a_{\sigma(i)}) \leq k(a_{\sigma(i+1)}) \quad \text{for all } 1 \leq i < n,$$

and additionally, whenever $k(a_i) = k(a_j)$ and $i < j$, we have $\sigma^{-1}(i) < \sigma^{-1}(j)$. That is, equal-key elements appear in the output in the same left-to-right order as they did in the input.

Worked Example. Consider a list of student records sorted first by grade, then by name. Suppose the input is:

$$[(B, \text{Zara}),\ (A, \text{Mia}),\ (B, \text{Ada}),\ (A, \text{Leo})]$$

A stable sort by grade alone yields:

$$[(A, \text{Mia}),\ (A, \text{Leo}),\ (B, \text{Zara}),\ (B, \text{Ada})]$$

Because the algorithm is stable, Mia precedes Leo (both grade $A$) and Zara precedes Ada (both grade $B$), mirroring their original positions. An unstable sort might instead produce $(A, \text{Leo}), (A, \text{Mia}), \ldots$, silently corrupting a secondary ordering already present in the data.

Key Theorem. Merge Sort is stable and runs in $\Theta(n \log n)$ time. During the merge step, when two elements share the same key, the merge procedure always takes the element from the left sub-array first, thereby preserving original order. No comparison-based sorting algorithm can achieve better than $\Omega(n \log n)$ worst-case comparisons (by the decision-tree lower bound), so Merge Sort is asymptotically optimal among stable comparison sorts.

Stability matters practically whenever records carry multiple attributes and are sorted in successive passes — a common pattern in database ORDER BY pipelines and radix-sort implementations.

Lab Cell.

from sympy import symbols
records = [('B','Zara'), ('A','Mia'), ('B','Ada'), ('A','Leo')]

# Python's built-in sort is guaranteed stable (Timsort)
stable_result = sorted(records, key=lambda r: r[0])
print(stable_result)
# [('A','Mia'), ('A','Leo'), ('B','Zara'), ('B','Ada')]

# Verify stability: among equal keys, original indices are preserved
grades = [r[0] for r in stable_result]
assert grades == sorted(grades), "Result is sorted by grade"
pairs = [(r, stable_result.index(r)) for r in stable_result]
print(pairs)

Run this cell and confirm that equal-grade entries retain their original relative order, illustrating stability concretely before moving to algorithmic proof.
