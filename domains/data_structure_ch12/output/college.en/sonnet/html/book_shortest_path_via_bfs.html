Concept Book: Shortest Path Via Bfs

Data Structure Ch12 · Generated by SPL

Payoff

Every idea in this book has been building toward a single guarantee: breadth-first search (BFS) finds a shortest path in an unweighted graph. Given a graph $G=(V,E)$ and a source $s$, BFS computes $d(s,v)$, the minimum number of edges from $s$ to every reachable vertex $v$, in $O(|V|+|E|)$ time. It is the natural endpoint because it uses everything before it: the graph representation, the queue's first-in-first-out discipline, and the idea of a visited set. They combine into one provable result.

Why it works

BFS processes vertices in nondecreasing order of distance. Let $L_k=\{v : d(s,v)=k\}$. The queue holds all of $L_k$ before any of $L_{k+1}$. When $u\in L_k$ is dequeued, each unvisited neighbor $w$ must lie in $L_{k+1}$. That is because $w$ is adjacent to a vertex at distance $k$, so $d(s,w)\le k+1$, and it was not discovered earlier, so $d(s,w)>k$. Induction on $k$ gives $\text{dist}[v]=d(s,v)$ for every reachable $v$. Recording each vertex's parent as it is discovered lets you walk backward from the target to recover an actual path.

Worked example

Take edges $A\!-\!B$, $A\!-\!C$, $B\!-\!D$, $C\!-\!D$, $D\!-\!E$, with source $A$ and target $E$.

from collections import deque

def shortest_path(adj, s, t):
    parent = {s: None}
    q = deque([s])
    while q:
        u = q.popleft()
        if u == t:
            break
        for w in adj[u]:
            if w not in parent:
                parent[w] = u
                q.append(w)
    if t not in parent:
        return None
    path = []
    while t is not None:
        path.append(t)
        t = parent[t]
    return path[::-1]

The levels are $L_0=\{A\}$, $L_1=\{B,C\}$, $L_2=\{D\}$ and $L_3=\{E\}$. The function returns ['A','B','D','E'], which has length 3. Notice that $D$ is reached first through $B$. The check w not in parent stops $C$ from rewriting it, and that check is also what keeps the running time linear.

Connections to applications

The same pattern applies wherever you can name the vertices and the "one step" relation:

  • Maze and grid navigation: cells are vertices and legal moves are edges. BFS gives the fewest moves.
  • Social networks: "degrees of separation" is $d(s,v)$ between two people.
  • Puzzles and state spaces: a Rubik's-cube-style puzzle or word ladder treats each configuration as a vertex and each legal move as an edge. The shortest path is the minimum number of moves.
  • Network routing: with hop count as the metric, BFS finds the route that crosses the fewest links.

    • Problem-solving checklist

  • Define the vertices, the neighbor rule, the source, and the goal.
  • Check that every step costs the same. If edges carry different weights, BFS no longer applies and you need Dijkstra's algorithm.
  • Run BFS with a parent map, and reconstruct the path.
