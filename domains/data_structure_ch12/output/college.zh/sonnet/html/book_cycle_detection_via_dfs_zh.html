一、DFS 环检测达成了什么

在有向图 $G=(V,E)$ 中,环是一条起止于同一顶点的非平凡路径。DFS 为每个顶点维护三种颜色:白色(未访问)、灰色(正在递归栈中)、黑色(已完成)。

定理(白路径与灰边):$G$ 含有环,当且仅当 DFS 过程中出现一条指向灰色顶点的回边。

证明要点:若遇到边 $(u,v)$ 且 $v$ 为灰色,则 $v$ 在递归栈中,即存在从 $v$ 到 $u$ 的树路径,加上边 $(u,v)$ 即构成环。反之,设环 $C$ 上第一个被发现的顶点为 $v$,则 $C$ 上其余顶点在 $v$ 变黑之前都是 $v$ 的后代,环上指向 $v$ 的最后一条边必然在 $v$ 仍为灰色时被检查到。$\blacksquare$

算法对每个顶点和每条边各处理一次,时间复杂度为 $O(|V|+|E|)$。

它是本书自然的终点,因为它汇集了前面所有内容:图的表示、递归与栈、顶点状态的归纳论证,以及对边的分类。它也把一个"全局"性质(是否存在环)化为一个"局部"检查(是否碰到灰色顶点)。

二、一个具体的例子

考虑依赖关系 $A\to B\to C\to A$,另有 $C\to D$。从 $A$ 出发:$A$、$B$、$C$ 依次变灰;在 $C$ 处检查边 $C\to A$ 时,$A$ 是灰色,立即报告环 $A\to B\to C\to A$。

def has_cycle(graph):
    color = {v: 0 for v in graph}          # 0白 1灰 2黑
    def dfs(u):
        color[u] = 1
        for v in graph[u]:
            if color[v] == 1: return True  # 回边
            if color[v] == 0 and dfs(v): return True
        color[u] = 2
        return False
    return any(color[v] == 0 and dfs(v) for v in graph)

三、与各应用领域的联系

本节未列出具体的应用领域,下面给出三个最常见的方向,它们都是同一个判据的不同"外衣":

  • 构建系统与包管理:模块之间的依赖是有向边。有环意味着循环依赖,构建无法排序。无环时,按 DFS 完成时间的逆序即得拓扑排序。
  • 死锁检测:在"等待图"中,线程 $T_i\to T_j$ 表示 $T_i$ 等待 $T_j$ 持有的锁。图中存在环,当且仅当(单实例资源下)发生死锁。
  • 课程先修关系与工作流:课程表若存在环,则无法修完。工作流引擎(如 DAG 调度器)在提交任务前必须先做环检测。

    • 练习:给定先修关系 $\{1\to2,\ 2\to3,\ 3\to4,\ 4\to2\}$,请追踪 DFS 的颜色变化,指出哪条边是回边,并写出对应的环。

    四、继续探索

    建议你选择一个方向深入:亲手为一个小型项目(例如你自己的 Python 包依赖)构建依赖图,运行环检测,并在无环时输出拓扑排序。当你看到算法在真实数据上指出一个你从未察觉的循环依赖时,就会体会到:一条简单的"遇到灰色顶点"的规则,足以守护复杂系统的秩序。
