Concept Book: Yfasttrie

Data Structure Ch13 · Generated by SPL

Payoff

A textbook on integer data structures builds toward a single unifying question: can we do better than comparison-based search? The y-fast trie, introduced by Willard (1983), answers that question decisively for the predecessor problem on a bounded integer universe $\{0, 1, \ldots, U-1\}$.

What the y-fast trie achieves. Recall that any comparison-based structure requires $\Omega(\log n)$ time per query. The y-fast trie sidesteps this lower bound by exploiting the binary representation of keys. It stores $n$ integers in $O(n)$ space and supports predecessor, successor, insert, and delete in $O(\log \log U)$ worst-case time — a doubly-logarithmic bound that shrinks dramatically as $U$ remains fixed. For a 64-bit universe ($U = 2^{64}$), this is at most 6 operations regardless of $n$.

Construction in brief. Partition the $n$ stored keys into $\lceil n / \log U \rceil$ contiguous groups, each of size $\Theta(\log U)$. Elect one representative per group and insert those representatives into an x-fast trie — a bitwise perfect-hash structure supporting predecessor on representatives in $O(\log \log U)$ time and $O(n)$ expected space. Within each group, maintain the keys in a balanced binary search tree (or a doubly-linked sorted list). A query locates the correct group in $O(\log \log U)$ via the x-fast trie, then resolves within $O(\log \log U)$ comparisons because each group has $O(\log U)$ elements.

Key theorem. A y-fast trie over $n$ keys drawn from $\{0,\ldots,U-1\}$ supports predecessor, successor, insert, and delete in $O(\log \log U)$ expected time per operation and $O(n)$ expected space.

The proof follows from the x-fast-trie cost analysis combined with the group-size invariant, which guarantees that no group ever exceeds $2\log U$ keys after any sequence of updates.

Connection to fusion trees. The y-fast trie optimizes along the universe axis: time depends on $\log \log U$, not $n$. The fusion tree of Fredman and Willard (1993) optimizes along the input-size axis, achieving $O(\log_w n)$ time per operation by packing multiple keys into a single machine word and executing parallel comparisons in $O(1)$. These two structures are complementary: when $U$ is large and $n$ is moderate, y-fast tries win; when $n$ is large and word size $w$ is fixed, fusion trees dominate. Composing both ideas yields asymptotically optimal integer search across all regimes — a synthesis that defines the frontier of succinct integer dictionaries.

import sympy as sp

U, n, w = sp.symbols('U n w', positive=True, integer=True)

yfast_time   = sp.log(sp.log(U, 2), 2)
fusion_time  = sp.log(n, 2) / sp.log(w, 2)

print("y-fast trie query time  :", yfast_time)
print("fusion tree  query time :", fusion_time)
print("y-fast wins when        :", sp.simplify(yfast_time < fusion_time))

To see these ideas meet hardware reality — where $w = 64$ and the word-level parallelism of fusion trees becomes concrete bit manipulation — turn to the next chapter on fusion trees, where the boundary between algorithm and architecture dissolves entirely.
