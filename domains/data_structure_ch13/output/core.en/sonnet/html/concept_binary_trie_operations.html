Binary Trie Operations

Definition

A binary trie (from retrieval) is a rooted tree in which every internal node has exactly two children, labeled $0$ and $1$. Each root-to-leaf path spells out a binary string, and the set of all such strings constitutes the language of the trie. Formally, let $\Sigma = \{0,1\}$ and $\Sigma^ $ denote the set of all finite binary strings. A binary trie $T$ over a finite set $S \subseteq \Sigma^$ is the minimal prefix-closed tree satisfying: for every $w \in S$, every prefix of $w$ appears as a node of $T$.

Three primitive operations define the interface:

  • Insert$(w)$: Follow the path $w_1, w_2, \ldots, w_n$ from the root, creating any missing nodes, and mark the terminal node.
  • Search$(w)$: Traverse the same path; return true if and only if the terminal node is marked.
  • Delete$(w)$: Unmark the terminal node of $w$ and prune any newly childless, unmarked nodes upward toward the root.

    • Each operation runs in $O(|w|)$ time and $O(|w|)$ worst-case additional space, where $|w|$ is the length of the query string.

    Worked Example

    Let $S = \{010, 011, 10\}$. Insert these strings in order.

    After inserting $010$: nodes $\varepsilon \to 0 \to 01 \to 010^\star$ are created (${}^\star$ marks terminal). After inserting $011$: the path shares $\varepsilon, 0, 01$; only node $011^\star$ is new. After inserting $10$: nodes $1 \to 10^\star$ are added under the root.

    Searching for $01$ returns false because node $01$ exists but is not marked. Deleting $011$ unmarks $011$ and prunes it (no children), but $01$ is retained because it still has child $010$.

    Key Theorem

    Theorem (Space complexity of a binary trie). A binary trie storing $n$ strings from $\Sigma^*$, each of length at most $L$, uses at most $nL$ nodes.

    Proof sketch. Each insertion traces a path of length at most $L$ and creates at most $L$ new nodes. Summing over all $n$ insertions gives the bound. Shared prefixes only reduce this count; hence $nL$ is a tight upper bound. $\blacksquare$

    In practice, when the stored strings share long common prefixes, the actual node count is $O(nL / \log n)$ for random binary inputs.

    Lab Cell

    from sympy import symbols, Function

class TrieNode:
    def __init__(self):
        self.children = {}   # keys: 0 or 1
        self.terminal = False

class BinaryTrie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, bits: str):
        node = self.root
        for b in bits:
            node = node.children.setdefault(b, TrieNode())
        node.terminal = True

    def search(self, bits: str) -> bool:
        node = self.root
        for b in bits:
            if b not in node.children:
                return False
            node = node.children[b]
        return node.terminal

trie = BinaryTrie()
for w in ["010", "011", "10"]:
    trie.insert(w)

print(trie.search("010"))   # True
print(trie.search("01"))    # False
print(trie.search("10"))    # True

    Running this cell confirms the worked example: $010$ and $10$ are found; the internal prefix $01$ is not.
