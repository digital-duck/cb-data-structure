摊还分析

定义

摊还分析是一种评估算法在一系列操作上平均代价的方法。与最坏情况分析不同，它不关注单次操作可能有多昂贵，而是问：如果执行 $n$ 次操作，总代价是多少？每次操作的摊还代价定义为：

$$\hat{c} = \frac{\text{总代价}}{n}$$

关键洞察在于：某些操作偶尔很昂贵，但这种高代价操作会为后续的廉价操作"提前买单"。只要总代价有界，整体效率就有保障。

典型例子：动态数组扩容

考虑 Python 的 list.append() 操作。列表底层是固定大小的数组，当空间不足时，Python 会将数组容量翻倍，并将所有元素复制到新数组。

假设从容量 1 开始，依次执行 $n$ 次 append：

  • 第 1 次：容量满，复制 1 个元素，代价 $O(1)$（初始化）
  • 第 2 次：扩容，复制 1 个元素，代价 $O(2)$
  • 第 4 次：扩容，复制 3 个元素，代价 $O(4)$
  • 第 $2^k$ 次：扩容，代价 $O(2^k)$

    • 扩容总代价为 $1 + 2 + 4 + \cdots + n = O(n)$，再加上 $n$ 次普通插入，总代价为 $O(n)$。因此每次 append 的摊还代价为 $O(1)$。

    解题应用

    分析带有"偶发昂贵操作"的数据结构时，使用聚合法（Aggregate Method）：

  • 计算 $n$ 次操作的总代价上界
  • 将总代价除以 $n$，得到每次操作的摊还代价
    • # 演示：记录每次 append 的实际代价
import sys

lst = []
prev_size = sys.getsizeof(lst)
for i in range(20):
    lst.append(i)
    curr_size = sys.getsizeof(lst)
    if curr_size != prev_size:
        print(f"第 {i+1} 次 append：发生扩容，新大小 {curr_size} 字节")
        prev_size = curr_size

    运行后可以看到，扩容发生的频率越来越低，这正是摊还 $O(1)$ 成立的直观证据。

    摊还分析广泛用于评估栈、队列、并查集（Union-Find）等结构。遇到"大多数操作很快，偶尔一次很慢"的模式时，优先考虑摊还分析而非最坏情况分析——后者会高估实际成本，导致错误的算法选型决策。
