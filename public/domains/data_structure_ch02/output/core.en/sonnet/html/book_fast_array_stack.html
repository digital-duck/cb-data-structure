Concept Book: Fast Array Stack

Data Structure Ch02 · Generated by SPL

Payoff

The journey through sequential containers — from fixed-length arrays with their rigid capacity, through dynamic arrays whose size doubles on overflow, to linked lists that trade spatial locality for pointer flexibility — arrives at a single synthesis: the fast array stack. This structure retains the contiguous memory layout of an array while equipping every push and pop operation with an amortized constant-time guarantee. The result is a stack whose worst-case single operation costs $O(n)$ (during a resize), yet whose cost averaged over any sequence of $n$ operations satisfies

$$\frac{1}{n}\sum_{i=1}^{n} c_i = O(1),$$

where $c_i$ denotes the cost of the $i$-th operation. This is not an approximation; the potential-function argument (letting $\Phi = 2\,\lvert\text{size}\rvert - \lvert\text{capacity}\rvert$) makes the bound exact. The fast array stack is therefore the natural endpoint of the design progression: it sacrifices nothing compared to a linked-list stack in asymptotic throughput, while recovering the cache-line efficiency that pointer-chased structures surrender.

Connection to downstream topics. Every algorithm that processes a recursive structure without incurring actual recursion overhead depends on an efficient stack. Depth-first graph traversal replaces the call stack with an explicit fast array stack, keeping the $O(V + E)$ time bound intact while avoiding system-stack overflow on large graphs. Shunting-yard parsing of arithmetic expressions uses a pair of stacks — one for operators, one for operands — whose combined push and pop count is linear in the token stream; the amortized analysis carries through unchanged. Computational geometry relies on the same structure in Graham's convex-hull scan, where points are pushed and conditionally popped in a single left-to-right pass. In each setting, the defining invariant is identical: elements arrive and depart in last-in, first-out order, and the amortized $O(1)$ cost per element is what makes the enclosing algorithm linear overall.

# Lab: verify amortized cost empirically with SymPy bookkeeping
from sympy import symbols, summation, simplify

i, n = symbols('i n', positive=True, integer=True)
# resize at powers of 2: cost c_i = i if i is a power of 2, else 1
# Total cost upper bound via geometric series
resize_cost = summation(2**i, (i, 0, n))   # geometric partial sum
simplify(resize_cost / 2**n)               # → O(1) amortized per push

The convex-hull scan is particularly rewarding as a first deep dive: it connects the stack invariant to a geometric predicate, produces a visual output, and generalises immediately to three dimensions via the gift-wrapping algorithm. The next chapter takes up exactly that thread.
