均摊分析

回顾直觉

你可能已经知道，有些操作有时快、有时慢。比如动态数组（像 Python 的列表）在追加元素时，大多数时候只需 $O(1)$，但偶尔需要"扩容"——把所有元素复制到更大的空间，耗费 $O(n)$。这看起来很慢，但实际上用起来并不觉得慢，为什么？

深入结构

均摊分析（Amortized Analysis）的核心思想是：把偶发的高代价操作，平摊到整个操作序列中，算出每次操作的"平均实际成本"。

以动态数组为例。假设数组容量不足时，容量翻倍。从容量 1 开始，插入 $n$ 个元素：

  • 扩容发生在容量为 $1, 2, 4, 8, \ldots$ 时，复制次数分别为 $1, 2, 4, 8, \ldots$
  • 总复制次数 $\leq 1 + 2 + 4 + \cdots + n = 2n$

    • 因此，$n$ 次插入的总代价为 $O(n)$，每次操作的均摊代价为：

    $$\frac{O(n)}{n} = O(1)$$

    这就是说，虽然单次扩容很贵，但"平摊"下来每次插入只需常数时间。

    简单规律

    > 均摊代价 $= \dfrac{\text{总代价}}{\text{操作次数}}$

    当操作序列中有"罕见但昂贵"的步骤时，均摊分析帮我们看清真实的长期效率，而不是被最坏情况吓到。
