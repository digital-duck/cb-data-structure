收束(Payoff)

为什么队列操作是自然的终点

单链表(singly linked list, SLL)队列把前面学过的所有要素汇集到一个结构里:节点与指针、头尾哨兵、常数时间的局部修改,以及用不变式来论证正确性。

设队列维护两个指针 head 与 tail。入队(enqueue)在尾部追加节点,出队(dequeue)从头部摘除节点:

class Node:
    def __init__(self, val):
        self.val, self.next = val, None

class Queue:
    def __init__(self):
        self.head = self.tail = None
        self.n = 0

    def enqueue(self, v):          # O(1)
        node = Node(v)
        if self.tail: self.tail.next = node
        else:         self.head = node
        self.tail = node
        self.n += 1

    def dequeue(self):             # O(1)
        if not self.head: raise IndexError("empty")
        v = self.head.val
        self.head = self.head.next
        if not self.head: self.tail = None
        self.n -= 1
        return v

不变式:当 $n=0$ 时 head 与 tail 同为空;当 $n\ge 1$ 时,从 head 沿 next 恰好经过 $n$ 个节点到达 tail,且 tail.next 为空。两个操作都只修改常数个指针,因此

$$T_{\text{enqueue}}(n)=T_{\text{dequeue}}(n)=\Theta(1).$$

相比之下,若只保留 head 指针,入队需遍历全表,代价为 $\Theta(n)$。维护 tail 指针这一设计,正是整章的核心收获:用额外的 $O(1)$ 空间,换取最坏情况下的常数时间。

这也是自然终点的原因:你必须同时处理空表、单节点、一般情形这三类边界,并用不变式证明它们都成立。这是后续一切指针型数据结构的标准训练。

与应用领域的联系

本节未列出具体的应用领域,因此下面只讨论队列的先进先出(FIFO)性质在典型场景中的作用,请把它们当作示例,而不是既定清单:

  • 任务调度:操作系统与任务系统按到达顺序处理请求。链表队列无需预先确定容量,适合请求量波动的场景。
  • 广度优先搜索(BFS):设图有 $V$ 个顶点、$E$ 条边。每个顶点至多入队、出队各一次,每次 $\Theta(1)$,因此总时间为 $\Theta(V+E)$。这个界依赖于队列操作的常数时间。
  • 缓冲与流处理:生产者与消费者以不同速率工作,队列在二者之间平滑负载,而且入队与出队分别只触及两端,便于并发控制。
