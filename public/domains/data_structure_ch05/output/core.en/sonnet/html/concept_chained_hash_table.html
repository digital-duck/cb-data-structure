Chained Hash Table

Definition. A chained hash table is a data structure that maintains an array $T$ of $m$ slots, where each slot $T[i]$ is the head of a singly-linked list (called a chain) containing all keys $k$ satisfying $h(k) = i$. Given a universe of keys $U$ and a hash function $h : U \to \{0, 1, \ldots, m-1\}$, the table stores $n$ key–value pairs with an expected load factor $\alpha = n/m$. Formally, the structure is the triple $(T, h, m)$ together with the invariant

$$T[i] = \{k \in S \mid h(k) = i\}, \quad 0 \le i < m,$$

where $S \subseteq U$ is the current key set.

Worked Example. Let $m = 7$ and $h(k) = k \bmod 7$. Insert the keys $\{50, 700, 76, 85, 92, 73, 101\}$.

| Slot | Chain | |------|-------| | 0 | $700 \to 85$ | | 1 | $50 \to 92 \to 85$... |

More precisely: $h(50)=1$, $h(700)=0$, $h(76)=6$, $h(85)=1$, $h(92)=1$, $h(73)=3$, $h(101)=3$. Slots 1 and 3 each carry chains of length 2; searching for key $85$ requires traversing two nodes in slot 1.

Key Theorem (Expected Search Time). Under the Simple Uniform Hashing Assumption (SUHA)—each key is equally likely to hash to any of the $m$ slots independently—an unsuccessful search visits an expected $\alpha$ nodes, and a successful search visits an expected $1 + \alpha/2$ nodes. Consequently, if $n = O(m)$ so that $\alpha = O(1)$, all dictionary operations (INSERT, DELETE, SEARCH) run in $O(1)$ expected time.

Proof sketch. For an unsuccessful search, the expected chain length is $\mathbb{E}[|T[h(k)]|] = n/m = \alpha$ by linearity of expectation and SUHA. For a successful search on key $k_i$ (the $i$-th key inserted), the expected number of keys inserted after $k_i$ that collide with it is $(n-i)/m$; summing and averaging over all $n$ keys yields $1 + \alpha/2$.

Lab Cell.

from sympy import symbols, Integer, Rational, simplify

m, n = symbols('m n', positive=True)
alpha = n / m

expected_unsuccessful = alpha
expected_successful   = 1 + alpha / 2

print("Unsuccessful search:", simplify(expected_unsuccessful))
print("Successful search:  ", simplify(expected_successful))

# Concrete check: n=7, m=7 → alpha=1
print("alpha=1, successful:", expected_successful.subs({n: 7, m: 7}))

Running this cell confirms the analytic expressions and instantiates them for $\alpha = 1$, predicting an average of $1.5$ comparisons per successful lookup—consistent with the worked example above.
