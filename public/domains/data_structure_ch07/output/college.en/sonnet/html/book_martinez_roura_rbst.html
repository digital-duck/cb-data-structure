Payoff

What the randomized binary search tree achieves

A binary search tree (BST) built from $n$ keys in random order has expected depth $\approx 2\ln n$. In the worst case, such as sorted input, its depth is $n-1$. Martínez and Roura's randomized binary search tree (RBST) removes that dependence on input order. The tree's shape is random, whatever sequence of insertions and deletions produced it. That is why it is a natural endpoint. It turns an average-case result into a guarantee that holds for every input.

The mechanism is a single local rule. To insert $x$ into a tree $T$ of size $n$, make $x$ the root with probability $\frac{1}{n+1}$. Otherwise, insert recursively into the left or right subtree by key comparison. When $x$ becomes the root, split $T$ around $x$ into trees $L$ and $R$ and attach them as its children. To delete, join the two subtrees $L$ (size $m$) and $R$ (size $k$). The root of $L$ becomes the new root with probability $\frac{m}{m+k}$, and otherwise the root of $R$ does. Each rule is the exact probability that a uniformly random permutation would choose that key as root.

Worked check

Insert keys $1,2,3$ in sorted order. A plain BST always yields the path $1\to2\to3$. In an RBST, the final tree is one of the five possible shapes, with the same probabilities as for a random permutation. For example, the root is $1$, $2$ or $3$ each with probability $\tfrac13$. The expected search cost is then $\le 2\ln n + O(1)$, and the cost of insertion and deletion is the same order.

Problem-solving use

To bound the cost of an operation, you never analyze the input. You analyze the random-permutation model. For example, the expected number of rotations or splits during an insertion is $O(\log n)$. This follows from the same recurrence that gives the expected depth, $C_n = 1 + \frac{1}{n}\sum_{i}(\dots)$.

Applications

You did not list any application domains, so I won't invent connections. Natural candidates include ordered dictionaries, which need robustness against adversarial or sorted input. Others are order-statistic queries, since the tree stores subtree sizes, and database indexes, where insertion order is outside your control. Treaps are a close relative, because they randomize with stored priorities instead of subtree sizes.
