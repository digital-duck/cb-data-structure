Concept Book: Yfasttrie

Data Structure Ch13 · Generated by SPL

Payoff

Every structure in this book was built to answer one question: how fast can we search an ordered set of $n$ keys drawn from a universe $U=\{0,\dots,2^w-1\}$? Balanced trees answer in $O(\log n)$. A van Emde Boas tree answers in $O(\log w)$ but costs $\Theta(2^w)$ space. The y-fast trie reaches the same $O(\log w)$ predecessor and successor time using only $O(n)$ space. That combination is what makes it the natural endpoint.

What the y-fast trie achieves

Three ideas combine:

  • An x-fast trie stores every prefix of every key in a hash table. A binary search over prefix lengths finds the longest stored prefix of a query $q$ in $O(\log w)$ expected time, and leaf links then give the predecessor. The cost is $O(n w)$ space.
  • Bucketing partitions the sorted keys into groups of size $\Theta(w)$, each held in a balanced search tree.
  • The x-fast trie indexes only one representative per bucket. The trie then holds $O(n/w)$ keys, so its space is $O\!\left(\frac{n}{w}\cdot w\right)=O(n)$.

    • Worked example. Take $w=16$ and $n=2^{12}$ keys. An x-fast trie would store about $n\cdot w = 65{,}536$ prefix entries. A y-fast trie uses buckets of size about 16, so it has $n/w=256$ representatives. It stores $256\cdot 16=4096$ entries, which is $O(n)$. A query costs $\log_2 16=4$ hash probes to find the right bucket. It then costs $O(\log w)=4$ more steps inside the bucket's tree. The total is $O(\log w)$, compared with $\log_2 4096=12$ comparisons for a plain balanced tree. Insertions and deletions cost $O(\log w)$ amortized, because a bucket is split or merged only after $\Theta(w)$ updates.

    The bound $O(\log w)$ beats $O(\log n)$ whenever $w=o(n^{\epsilon})$ for every $\epsilon>0$, for example when $w=O(\log n)$ or $w=\text{polylog}(n)$. This is the usual case for machine words.

    Connection to fusion trees

    Fusion trees attack the same problem from the other side. Instead of exploiting the word length through prefixes, they exploit word-level parallelism. A node packs $k=w^{1/5}$ keys. A sketch of only $O(k^4)$ bits distinguishes them, and one multiplication compares a query against all of them at once. Each level then costs $O(1)$, and the height is $O(\log_w n)$. Together, the two structures give the classic bound:

    $$T(n)=\min\bigl(\log w,\ \log_w n\bigr)\le O\!\left(\sqrt{\log n}\right).$$

    The y-fast trie is the better choice when $w$ is small relative to $n$. The fusion tree is the better choice when $n$ is small relative to $2^{\sqrt{w}}$. Fusion trees reuse three ideas you now own: a hashed or compressed key representation, a small number of keys per node (as in the y-fast trie's buckets), and an $O(1)$ step at each level.

    Problem to try. For $w=64$, compare $\log_2 w$ with $\log_w n$ for $n=2^{20}$ and $n=2^{40}$. Which structure wins in each case? Where is the crossover?

    An invitation

    Pick up the fusion tree next. Start with its key trick, the sketch. Choose a set of bit positions that distinguishes all $k$ keys, then compress those bits into a short word with one multiplication. Work through why the sketch preserves order, then see how that makes $O(1)$-time node search possible. You will find that the y-fast trie taught you to ask "how many bits matter?" The fusion tree is the most ingenious answer to it.
