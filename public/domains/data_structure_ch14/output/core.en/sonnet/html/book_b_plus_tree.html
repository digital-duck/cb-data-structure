Concept Book: B Plus Tree

Data Structure Ch14 · Generated by SPL

Payoff

A B+ tree is an ordered, balanced search tree in which all data records are stored exclusively in the leaf nodes, while internal nodes serve purely as routing keys. More precisely, given a positive integer $t$ called the minimum degree, a B+ tree of order $t$ satisfies: every internal node holds between $t-1$ and $2t-1$ keys; every internal node except the root has between $t$ and $2t$ children; all leaf nodes reside at the same depth $h$; and the leaves are linked in a doubly-linked list ordered by key. The height of a tree storing $n$ keys obeys

$$h \leq \log_t\!\left(\frac{n+1}{2}\right),$$

guaranteeing that search, insertion, and deletion each complete in $O(\log_t n)$ key comparisons.

Worked example. Consider a B+ tree of order $t = 2$ (so each internal node holds 1–3 keys and 2–4 children) storing the integer keys $\{1, 4, 7, 10, 17, 21\}$. A valid tree places the routing key $10$ at the root, with left subtree routing on $\{4, 7\}$ and right subtree routing on $\{17\}$. The six leaves, each containing one data record, form the sorted chain $1 \leftrightarrow 4 \leftrightarrow 7 \leftrightarrow 10 \leftrightarrow 17 \leftrightarrow 21$. A range query for all keys in $[4, 17]$ requires a single root-to-leaf descent of cost $O(\log_t n)$ to locate key $4$, followed by a linear scan along the leaf chain — a pattern impossible to replicate efficiently with a plain binary search tree or a hash map.

Key theorem (range-query optimality). Let $T$ be a B+ tree of order $t$ storing $n$ keys. A range query $[k_1, k_2]$ returning $r$ records executes in $O(\log_t n + r)$ time and requires at most $\lceil r / (t-1) \rceil + O(\log_t n)$ disk page reads. This bound is asymptotically optimal among comparison-based structures on a block-transfer memory model.

Connection to applications. The theorem above is precisely why B+ trees are the index structure of choice in both of the domains this text has built toward.

In filesystems, the HFS+, NTFS, and ext4 directory layers organise file-system metadata — inode numbers, directory entries, extent maps — in on-disk B+ trees. The block size of the tree node is matched to the storage device's sector or page size, minimising the number of physical I/O operations needed to traverse a deep directory hierarchy or locate a file's data extents.

In relational databases, every major engine (PostgreSQL, MySQL InnoDB, SQLite) implements table clustered indexes and secondary indexes as B+ trees. A query such as SELECT * FROM orders WHERE date BETWEEN '2024-01-01' AND '2024-03-31' is translated directly into the range-query algorithm of the theorem above: one descent to the first qualifying leaf, then a sequential scan along the linked leaf list, reading only the pages that contain matching rows.

The leaf-link is the structural feature that unifies both domains: it converts a hierarchical index into a sorted sequential file at no extra storage cost, enabling both point lookup in logarithmic time and range scan in output-proportional time simultaneously.

Lab cell.

from sympy import symbols, ceiling, log, simplify

t, n, r = symbols('t n r', positive=True, integer=True)

height_bound   = ceiling(log(n, t))
range_cost     = height_bound + r
print("Height bound  :", height_bound)
print("Range-query cost (disk reads) :", range_cost)

# Concrete instance
t_val, n_val, r_val = 100, 10**6, 500
print(f"\nt={t_val}, n={n_val:,}, r={r_val}")
print("Max height    :", ceiling(log(n_val, t_val)))
print("Range cost    :", int(ceiling(log(n_val, t_val))) + r_val)

Running this cell for $t = 100$, $n = 10^{6}$, and $r = 500$ reveals that a database serving half a million daily queries can answer each range scan touching 500 rows in at most 503 page reads — a depth of just 3. The algebraic simplicity of this bound is the payoff that decades of index-structure research have been building toward.
